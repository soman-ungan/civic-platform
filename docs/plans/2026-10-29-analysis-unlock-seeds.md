# 分析と投稿を開く条件を「最初の意見すべて」にし、自分の意見には自動で賛成を入れる

## Context
フェーズ6b では、分析（みんなの意見）を見られる条件を「最初の意見すべてと、合わせて15件（意見がそれより少なければ全部）」にした。
動作確認で、意見が15件より少ないトピックでは次のことが起きた（2026-10-29 ユーザーの確認）。

1. 最初の意見にすべて投票する → 分析が開く
2. 自分の意見を投稿する → 意見の総数が増えて、分析が閉じる
3. 自分の意見に投票する → 分析が開く

他の人の意見が承認されたときも同じように閉じる。また、自分で書いた意見に自分で投票を求められるのも奇妙。

## 決めたこと（2026-10-29 ユーザーと決定）
1. **分析を見られる条件は「最初の意見すべてに投票した」だけにする**（15件の条件をなくす）
   - 公開中のトピックに足される意見は最初の意見にならない（ADR 0005）ので、公開後に一度開いた分析は閉じない
   - 最初の意見はどの参加者にも同じなので、条件が人によってぶれない
   - 「全体の傾向を見る前に自分の考えで投票してもらう」目的は、議会での主張（最初の意見）への投票で保つ
   - 最初の意見が少ないトピックは、公開の前に運営者が確かめる（ADR 0005 のとおり。下限は設けない）。最初の意見が無いトピックは、すぐに開く
2. **意見を投稿したら、その人の賛成の票を一緒に保存する**（Polis と同じ）
   - 自分の意見が次の意見に出てこない。書いた人の立場が意見マップに入る
   - 保存するのは、投稿を保存したとき（承認・承認待ち・確認待ち）。非公開（rejected）と似た意見（保存しない）には入れない
3. **投稿できる条件も「最初の意見すべて」のまま**（分析と同じ）。「すべての意見に投票したら投稿できる」は採らない
   - 意見は参加者に比例して増えるので、後から来た人ほど投稿までの投票が増える（参加の時期で決まりが変わる）
   - 他の人の意見が承認されるたびに条件が揺れ、書いている途中で投稿できなくなる
   - 投稿のためのパスの連打が分析を濁らせる。似た意見は AI の案内で防げている

## やること
- `backend/src/process/progress.rs`: `analysis_remaining` を未投票の最初の意見の数にする。`ANALYSIS_UNLOCK_VOTES` を消す
- `backend/src/interface/api/participation.rs`: 投稿を保存したら（rejected 以外）、投稿者の賛成の票（`vote_value = 1`）を入れる
- テスト（`tests/participation_rules.rs`・`api_participation.rs`・`review.rs`）を新しい条件に合わせ、次を足す
  - 最初の意見すべてで開く（15件に届かなくても）。意見が増えても閉じない
  - 投稿したら自分の賛成が入り、次の意見に自分の意見が出ない。rejected・duplicate には入らない
- 画面の文言（`components/analysis/panel.tsx`・`participation/voting-panel.tsx`）を「最初の意見」に合わせる
- ドキュメント: ADR 0005 の改訂（理由を残す）、CLAUDE.md、`docs/polis-math.md`

## 確認
- `cargo test`、frontend の lint・typecheck・build
- 手元のブラウザで、上の 1〜3 の流れで分析が閉じないこと（ユーザーに見てもらう）

## しないこと
- 投稿の条件を分析と分けること（3 のとおり）

## 実装時の変更点
- **タイムラインの合意点（`/consensus`）は、1件以上投票したトピックだけにした**: 最初の意見が無いトピックは投票しなくても分析が開くので、「分析を見られる」だけでは、参加していないトピックの合意点まで出てしまうため（前は意見が0件のトピックだけを外していた）
- テストの fixture には最初の意見が無いものがあるので、分析・投稿の条件を確かめるテストでは、意見を最初の意見にしてから確かめる

## 追加: 最初の意見の段階を、進み具合で見せる（2026-10-29 ユーザーと決定）
- 最初の意見のカードだけ色を変える案は採らない。権威や党派への反応で票が動く、市民の意見が格下に見える、分析が偏る、公開中に足した議会の主張には印が付かずちぐはぐ、のため（Polis もすべての意見を同じ見た目で出す）
- 代わりに、進み具合の `progress` に `seeds_voted`・`seeds_total` を足し、「最初の意見 3 / 5」と、終えた直後に「ここからは、参加した人が投稿した意見です」を出した。動作確認のあと、どちらも削った（ユーザーと決定）。進み具合の下の「あと N 件で…」の文も削り、段階の説明は「みんなの意見」のロックの画面だけにする
- 出どころ（議会の主張であること・会議録へのリンク）を投票のあとに分析の画面で見せるのは、6c の後の UI の調整で考える

## 追加: 投稿の条件は、投票を先に見る（2026-10-29）
- 動作確認で、未登録の人には、最初の意見に投票する前から「自分の意見を追加」が見えていた。`post_permission` が登録を先に見て `registration_required` を返し、画面はそれをボタン（押すとパスキーの案内）で出していたため
- 投票の条件（最初の意見すべて）を先に見るようにした。未登録でも、最初の意見を終えるまでは `votes_required`（API は 403）

## 追加: ロックの間は、投票のボタンより下へスクロールさせない（2026-10-29 ユーザーと決定）
- 投票の前に、ボタンより下（投稿の案内・「みんなの意見」のロックの画面）へスクロールできるのが不自然だったため
- ロックの間は、投稿の欄をボタンのすぐ下で少しだけ見せて切り（下をぼかす）、「みんなの意見」は出さない。スクロールはそこで止まり、端末の弾む動きで戻る（JS でスクロールを戻す案は、慣性スクロールと取り合うので採らない）
- 投稿の欄の案内を「あと N 件投票すると、『みんなの意見』が見られ、自分の意見も投稿できます」にした（ロックの画面の代わり）。ロックの画面の理由の説明は、この画面では出なくなる
