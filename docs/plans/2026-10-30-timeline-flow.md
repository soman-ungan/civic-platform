# タイムラインの流れ（自動公開・並び順・新着・会期）

## Context
会議録の1日分から最大15件の下書きを作るので、下書きがたまる（2026-10-30 の手元の DB で35件）。ADR 0005 は「下書きを少しずつ公開し、タイムラインに日々議題が上がるようにする」と決めているが、作り方は未定だった。
タイムラインは作った日（`created_at`）の順に並ぶので、少しずつ公開すると古い会議録のトピックが下に埋もれる。会議録から作ったトピックの会期も、カードに出ていない（ADR 0005「会議の日を目立たせて出す」）。

タイムラインの設計は2つに分ける（2026-10-30 ユーザーと決定）。これは A。
- A（この計画）: 自動公開・並び順・新着の印・会期の表示
- B（あと）: 最初の意見の数と1人の投稿数、トピックの「この分野のお金」の年度の照合と表示（予算・決算とも総額。1人あたりは出さない）

## 決めたこと（2026-10-30 ユーザーと決定）
- **自動公開**: 運営者は下書きを確かめて「公開待ち」に入れる。決まった時刻に、待ちの古い順（先入れ先出し）に1件ずつ公開する。急ぐものは今までどおり手で公開する
- **公開の時刻と件数は、管理画面で足す・消す・変える**（ローンチ後のトピックの数に合わせて変えるため）。時刻を1つ足すと、1日の件数が1件増える。自治体ごとに持つ
- **新着の印**: 公開から3日以内で、まだ投票していないトピック
- **会期の表示**: 年・回・月（例「令和8年 第2回定例会（6月）」）。会議の日付は出さない（出典の引用に日付があるので）
  - 年と回は、会議録の資料名から読む（「令和８年第２回大田原市議会定例会（第３号）」→ 令和8年・第2回・定例会）。資料名の「令和8年」は暦年（第1回定例会は2〜3月）なので、年度とは書かない
  - 月は、そのトピックの出典の会議の月（`documents.held_on`。複数あれば最初）
  - 資料名から読めないときは、資料名から末尾の「（第N号）」を除いたものを出す

## やること

### Step 1 DB（新しいマイグレーション）
- `topics.queued_at`（公開待ちに入れた日時。NULL は入っていない）。`status` は draft のまま（下書きが外に出ない決まりは変わらない）
- `publish_slots`（`id`・`municipality_id`・`time_of_day`（日本時間の `HH:MM`）・`last_run_on`（最後に公開した日。日本時間の `YYYY-MM-DD`）・`created_at`）。`(municipality_id, time_of_day)` に UNIQUE

### Step 2 自動公開（`records/topics.rs`・`process/publishing.rs`）
- 公開待ちに入れる・外す（下書きだけ）。公開・取り下げたら `queued_at` を消す
- 時刻の一覧・足す・消す・変える
- ワーカー（1分ごと）: 自治体ごとに、今日（日本時間）の時刻を過ぎていて、今日まだ動いていない枠があれば、待ちの古い順に1件を公開する（`set_status` と同じ処理。90日の期限が付く）。待ちが空なら、その枠は何もしない
  - backend が止まっていて時刻を逃しても、その日のうちに起動すれば公開する。日をまたいだ分はまとめて出さない
- CLI: `list queue`・`add queue --id`・`remove queue --id`、`list slot`・`add slot -m <slug> --at HH:MM`・`remove slot --id`

### Step 3 運営者の API と管理画面
- `POST` / `DELETE .../topics/{id}/queue`、`GET .../queue`（待ちの順と、公開の予定日時）、`GET` / `POST` / `PATCH` / `DELETE .../publish-slots`
- 管理画面: 下書きのカードに「公開待ちに入れる」。タブ「公開待ち」に、順番・予定日時・外すボタンと、公開の時刻の設定（足す・消す・変える）。待ちが空、または時刻が1つも無いときは知らせる

### Step 4 タイムラインの並び順と新着
- 一覧の並びを「受付中を先に、公開した日（`published_at`。NULL なら `created_at`）の新しい順」に
- 一覧に `is_new`（公開から3日以内で、その参加者が未投票）。判定は backend（`process/progress.rs`）。カードに「NEW」

### Step 5 会期の表示
- 一覧と詳細に `session`（`{label}`。議会のトピックだけ。例「令和8年 第2回定例会（6月）」）。資料名の読み取りは `records/minutes.rs`（全角数字も読む）
- カードと詳細のヘッダーの「議会」の横に出す

### Step 6 テストと docs
- 自動公開（時刻・先入れ先出し・その日のうちの取り戻し・待ちが空・2自治体で混ざらない・下書きが外に出ない）、並び順、新着、会期の読み取り
- ADR 0005 の追記、`design/schema.md`・`design/api.md`・`operations/cli.md`・`operations/data-flow.md`・`overview.md`・`plans/README.md`

## 実装時の変更点
- 運営者の API は、公開待ちと時刻をまとめて `GET .../publishing` で返し、時刻の追加・変更・削除の応答も同じ形にした（画面が1回で読み直せるように）。計画の `GET .../queue` は作らなかった（`.../statements` の確認待ちを管理画面で「queue」と呼んでいて紛らわしいため、タブの名前も `scheduled`）
- 公開待ちに入れた下書きは、管理画面の「下書き」の一覧（`?status=draft`）に出さない（受け箱として使えるように）。直すときは「外す（下書きに戻す）」。CLI の `list topic --drafts` には出る
- 下書きのカードのボタンは「公開待ちに入れる」を主にし、「今すぐ公開」「取り下げる」を並べた
- CLI に `edit slot --id --at` も足した（計画では add / remove だけ）
- 公開の予定（`planned_at`）は、今の時刻の設定のまま進んだときの見込み。時刻を過ぎてまだ動いていない枠は「今」（次のワーカーの番）とする
- 確かめ: `cargo test`（新しいテストを含め、すべて通る）・clippy・frontend の lint と型チェック。コピーした DB で起動し、公開待ちに2件入れ、1分後の時刻を足して、ワーカーが先頭の1件を公開し、タイムラインの一番上に新着・会期つきで出ることを確かめた
