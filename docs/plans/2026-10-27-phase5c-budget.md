# フェーズ5c（当初予算の概要の取り込みと「まちのお金」への予算の追加）実装計画

## Context
フェーズ5b で総務省の決算カードを取り込み、「まちのお金」を作った（PR #5）。決算カードは約2年遅れ（いまは2024年度まで）なので、今年度のお金の使い方が見えない。5c では、自治体の「当初予算の概要」の PDF から数字と事業の名前を取り出し、今年度の予算を見せる。

### ユーザーと決めたこと（2026-10-27）
1. 見せるもの: 今年度の予算の全体（款別・性質別・1人あたり）、予算と決算の比較、主な事業（名前・金額・新規/拡充・分野タグ）
2. **事業の説明の文章は載せない。** 原本の PDF のそのページへリンクする（市の著作物のため）
3. **画面の軸は全国で共通のもの（款と分野タグ）にする。** 近隣の市町（大田原市・那須町・那須烏山市・那須塩原市）の概要を比べたところ、主な事業の分け方が自治体ごとに違った（総合計画の政策・分野・基本目標、または款とテーマの記号）。政策の名前は、事業の補足として持つだけにする。概要版の章立て（市の並べ方）を再現しないことは、著作権の面でも安全
4. 数字と事業の名前だけを見せるので、情報政策課の返事を待たずに作り始める。本番での公開の時期は、返事を受けて決める

## 著作権の整理（法的な助言ではない）
- 数字・事業の名前・政策の名前・「どの事業がどの政策か」は事実なので使う
- 説明の文章・図・レイアウトは市の著作物（15条の職務著作）なので使わない
- 政策の体系をそのままの並びで再現するのは、編集著作物（12条）のおそれがあるので避ける
- PDF からの抽出（解析）は 30条の4 の範囲

## 方針
- 取得: `html_link_list` アダプタで、一覧ページから「当初予算の概要」の PDF を探す（リンクの文字と年度を `config` の正規表現で読む）。予算書の本体（約50MB）は使わない
- 抽出: Claude Opus 5.5 に PDF を渡し、構造化出力で受け取る（引用（citations）は構造化出力と同時に使えないため使わない）
  - 受け取るもの: 款別・性質別・歳入の額と合計、事業（名前・金額・新規/拡充・ページ・政策の名前・分野タグ）
  - 分野タグは、共通の語彙（`data/seeds/020_field_tags.sql`）の中から抽出と同じ呼び出しで選ばせる
- 確かめる処理（プログラム）
  - 款別・性質別・歳入の合計が一致すること。合わなければ保存しない
  - 事業の名前と金額が、AI が返したページの本文（`pdftotext`）にそのまま含まれること。含まれない事業は捨てる
  - 分野タグは語彙の中のものだけを残す
  - `pdftotext`（poppler-utils）は別のコマンドとして呼ぶ。PDF は一時ファイルに書き、確かめたら消す（原本を保持しない）
- 結果は下書きにし、運営者が `budget show` で確かめて `budget publish` で公開する
- 1人あたりの換算: 予算の年度の人口はまだ無いので、それ以前で最新の人口（決算カード）で割り、どの年の人口かを示す
- 費用: 1年分で 0.5〜1 ドルの見込み。実際の API を呼ぶ取り込みは、実行の前にユーザーの了承を得る

## Step 0: 計画の保存 → `docs: フェーズ5c の計画を追加`

## Step 1: テーブル → `feat(backend): 予算のテーブルを追加`
- `budgets`: 自治体・年度・状態（draft / published）・`document_id`・一覧ページと PDF の URL。`UNIQUE (municipality_id, fiscal_year)`
- `budget_items`: 予算の区分（歳入・目的別・性質別）と費目の額（千円）。費目のキーは決算カードと同じ表記（比較のため）
- `budget_projects`: 事業（名前・金額・新規/拡充・ページ・政策の名前）
- `budget_project_tags`: 事業と分野タグ

## Step 2: 抽出と確かめる処理 → `feat(backend): 予算の概要からの抽出`
- `backend/src/budget/`（抽出・ページの本文の取り出し・確かめる処理・保存）
- LLM の呼び出しに PDF（document ブロック）を渡せるようにする
- テスト: 偽の LLM と、作った小さな PDF の本文の代わりの文字で、合計の検算・ページに無い事業を捨てること・語彙に無いタグを捨てること

## Step 3: 取得と CLI → `feat(backend): 当初予算の概要の収集`
- `html_link_list` アダプタ（`collect run` で AI を使う。キーが無ければこのアダプタは止める）
- `cargo run -- import budget --municipality <slug> --file <pdf> --year <n> [--url] [--dry-run]`（手で取った PDF でも取り込める。ほかの自治体の試しにも使う）
- `cargo run -- budget drafts | show <slug> <year> | publish <slug> <year> | archive <slug> <year>`
- 大田原市の収集先を seed に追加（規約の確認日つき）

## Step 4: API → `feat(backend): まちのお金に予算を追加`
- `/finances` の年度に、予算だけの年度も含める。年度ごとに `budget`（区分ごとの額・1人あたり・主な事業）を返す。決算もある年度は両方を返す
- トピックの詳細の `finances` に、分野タグに対応する今年度の主な事業を足す

## Step 5: 画面 → `feat(frontend): まちのお金に予算と主な事業`
- 年度のボタンに「予算」の年度を足す。決算が無い年度は予算の数字で見せ、「予算」と分かるようにする
- 欄を足す: 「主な事業」（分野タグごと、新規・拡充の印、原本のページへのリンク）、「予算と決算」（款ごとに並べる。両方ある年度だけ）
- トピックの詳細に「この分野の今年の事業」

## Step 6: 実物での検証（ユーザーの了承のもと）
- 大田原市の令和8年度の概要で取り込み、下書きをユーザーと確かめる
- 那須町・那須烏山市の概要で `--dry-run` を試し、ほかの自治体でも使えるかを確かめる

## Step 7: ドキュメント → `docs: 予算の取り込みを記録`
- `collection.md`、CLAUDE.md（コマンド、poppler-utils が要ること）

## 確認
- `cargo test`、clippy、frontend の lint・typecheck・build、CI
- 実物の取り込みで、款別の合計が概要の表と一致すること、事業がページの本文と一致すること
