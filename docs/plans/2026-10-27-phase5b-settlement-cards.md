# フェーズ5b（決算カードの収集と「まちのお金」の可視化）実装計画

## Context
フェーズ5a（会議録の手動取り込みと AI によるトピック案）が完了した（PR #4）。5b では、行政資料の自動収集の土台（取得の共通処理と `Collector` trait）を作り、総務省の決算カードから自治体のお金の流れを「市民1人あたり」で見せる。

総務省の市町村の決算カードは、平成27年度以降、都道府県ごとの Excel で公開されている（https://www.soumu.go.jp/iken/zaisei/card.html）。全市町村が同じ形式なので、AI を使わず決まった手順のコードで読み取れる見込み。

設計は `docs/design/collection.md`（フェーズ4で作成）に従う。

### ユーザーと決めたこと（2026-10-27）
1. 5b は**総務省の決算カード**だけ。大田原市の予算書（PDF・AI で抽出）は 5c に回す
2. 専用のページ「まちのお金」を作り、決算カードの費目と分野タグの**対応表**（seed）で、トピックの詳細に関係する費目の数字を**機械的に**出す（AI は使わない）
3. 1人あたりの換算に使う人口・世帯数は、**決算カードに載っている値**を `municipality_stats` に入れる

## 方針
- **AI は使わない**。Excel は決まった手順のコードで読む（費用なし）
- **原本は持たない**。Excel は読み終えたら捨て、数値と出典（URL・ハッシュ・取得日時）だけを残す
- **都道府県名をハードコードしない**。自治体のマスタから都道府県と団体コードを引き、年度ごとの一覧ページからその都道府県の Excel のリンクを探す。自治体の追加は `collector_sources` の1行で済む
- **許可と規約の確認の記録が無い収集先は動かさない**（`terms_url` と `terms_checked_at` が無ければ、`is_enabled` でも取得しない）

## Step 0: 計画の保存 → `docs: フェーズ5b の計画を追加`
- この md を保存してコミット。`feat/phase5b` ブランチ、Draft PR

## Step 1: 調査（コードを書く前に）
- 総務省のサイトの robots.txt と利用規約（政府標準利用規約・CC BY 4.0 互換か）を確かめる
- 令和5年度・平成27年度の栃木県の Excel を1回ずつ取得し（`data/private/`）、シートの構成、団体の見分け方（団体コード／団体名）、費目の表記と年度による違い、.xls か .xlsx かを確かめる
- 結果を `collection.md` に記録し、読み取りの方法を決める（セルの位置を固定せず、見出しの文字で位置を探す想定）

## Step 2: 取得の共通処理と `Collector` trait → `feat(backend): 取得の共通処理と Collector trait`
- `backend/src/collect/fetch.rs`: すべての取得がここを通る。robots.txt（1日キャッシュ。最小限のパーサーを自前で書いてテスト）、1サイトあたり `min_interval_secs` 以上の間隔・並列にしない、ETag / Last-Modified の条件付き取得、1ファイル 100MB まで、連絡先入りの User-Agent（新しい環境変数 `COLLECTOR_CONTACT`）
- `Collector` trait と、`adapter` 名から実装を選ぶ処理。規約の確認の記録が無い収集先は止める
- テスト: ローカルの HTTP サーバーで、robots.txt で不許可の範囲に接続しない・間隔・304・大きさの上限

## Step 3: スキーマ → `feat(backend): 決算カードのテーブルを追加`
新しいマイグレーション（マージ済みのものは書き換えない）。
- `settlement_items`: 自治体・年度・区分（歳入／目的別歳出／性質別歳出／財政指標）・費目のキー・原表の表記・金額（千円）または指標の値・`document_id`。主キーは (municipality_id, fiscal_year, category, item_key)
- `settlement_item_tags`: 費目のキー → 分野タグ（全自治体で共通。seed）。例: 民生費 → 福祉・介護 / 子育て・教育、土木費 → 道路・上下水道 / まちづくり・地域、公債費 → 財政・税
- `fetch_cache`: URL ごとの ETag・Last-Modified・sha256・取得日時
- `municipality_stats` は既存のテーブルを使う（出典の URL は決算カード）

## Step 4: 決算カードのアダプタ → `feat(backend): 総務省の決算カードの収集`
- `soumu_settlement_card`: 年度ごとの一覧ページ → その都道府県の Excel → 団体コードで自分の自治体の部分 → 費目と人口を保存
- 対象は Excel のある平成27年度以降。未取得・更新された年度だけを処理する
- CLI: `cargo run -- collect list`（収集先・規約の確認日・最後の取得）／`collect run [--source <id>] [--year <n>] [--dry-run]`。定期実行はフェーズ7
- 大田原市の収集先を `010_municipality_092100_otawara.sql` に追加
- 読み取った金額の検算（目的別・性質別の合計が歳出の合計と一致すること）。合わない年度は保存しない
- 依存の追加: `calamine`（Excel を読む。MIT）、dev-dependency に `rust_xlsxwriter`（テスト用の Excel を作る。MIT/Apache-2.0）
- テスト: 作った Excel で、読み取り・検算・2自治体の取り違えがないこと。実物の Excel のテストは `data/private/` にあるときだけ（`#[ignore]`）

## Step 5: API → `feat(backend): まちのお金の API`
- `GET /municipalities/{slug}/finances?year=`: 年度の一覧、歳入の内訳、目的別・性質別の歳出（1人あたり・割合）、財政指標、人口、出典。推移のために費目ごとの全年度の値も返す
- トピックの詳細に `finances`: トピックの分野タグに対応する費目の、最新年度の額・1人あたり・割合

## Step 6: 画面 → `feat(frontend): まちのお金`
- `/[municipality]/finances`「まちのお金」: 「市民1人あたり年間〇〇円」を軸に、目的別の歳出と歳入の内訳、年度の切り替え、10年の推移、出典（総務省 決算カード・年度）。図は既存の `residency-dot-plot` と同じく SVG で手書き（ライブラリは足さない）
- タイムラインのヘッダーからリンク
- トピックの詳細に「この分野の市のお金」（「分野と費目の対応はおおまかです」と注記）
- スマホ幅で確かめる

## 実装時の変更点
- **`fetch_cache` は収集先ごと**（`(source_id, url)`）: 決算カードの Excel は県ごとに1つで、同じ県の自治体が同じ URL を使う。URL だけで記録すると、2つ目の自治体が「変化なし」になって取り込まれない
- **金額は千円の `BIGINT`、比率・指数は1000倍の整数（`unit = 'milli'`）**: PostgreSQL の `INTEGER` では大きな都市の歳出が収まらず、浮動小数点の誤差も避けるため（`llm_usage.cost_micro_usd` と同じ考え方）。原表の「-」は NULL
- **費目のキーは原表の表記（空白を除く）**: 決まった一覧を持たず、年度による費目の増減（「地方特例交付金」→「地方特例交付金等」など）もそのまま残す。目的別・性質別は10年すべてで同じ表記だった
- **依存の差し替え**: `rust_xlsxwriter` は足さず、読み取りをセルの一覧（`Grid`）に対して書き、テストではセルを直接組み立てた。代わりに `encoding_rs`（総務省のページが Shift_JIS のため。MIT/Apache-2.0）を足した。実物の Excel のテストは `data/private/` にあるときだけ（`#[ignore]`）
- **財政指標は、財政力指数・経常収支比率・実質収支比率・実質公債費比率・将来負担比率・地方債現在高**。積立金の現在高は内訳の合計が要るので今回は入れない
- **公債費と「財政・税」は対応させない**: 税の話題（国民健康保険税など）に借金の返済が並び、関係があるように見えて誤解を招くため
- **COLLECTOR_CONTACT はリポジトリの URL**（ユーザーと決定）。あわせて GitHub のユーザー名を moon-ungan から soman-ungan に変えた。調査の最初の1回だけ、User-Agent に運営者のメールアドレスを入れて総務省に接続してしまった（以後は外した）
- **実物の取り込みの結果**（2026-10-27）: 大田原市の平成27〜令和6年度の10年分。すべて検算を通過。令和5年度のカードの「前年度」の欄（歳出総額）が、令和4年度のカードの値と一致することを確認した。総務省の PDF 版との照合はユーザーに依頼中
- **画面の確認**: この環境にヘッドレスブラウザが無いため、スマホ幅の見た目の確認はユーザーに依頼（HTML と API の出力は確認済み）
