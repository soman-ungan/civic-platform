# 議員の記録（タブ「議会」）

## Context
ADR 0008 で、議員の仕事ぶり（議会で何を取り上げたか）を市民が見られるようにすると決めた（2026-10-31 ユーザーと決定。A「議員の記録」だけ。フェーズ7の前に作る）。
データは今ある `public_officials`（名簿）と `topic_sources`（トピックの出典。会議録の原文と一致する引用と `official_id`）だけを使う。AI は使わない。

## やること

### backend
- マイグレーション: `public_officials.name_kana`（並べ替えだけに使い、画面には出さない）。大田原市の seed に読みを足す（id のローマ字から。【要確認】公式の名簿で確かめる）
- `GET /api/municipalities/{slug}/officials` — 現職の首長・議員（首長が先、議員は読みの順）と、任期の終わった人のうち記録のある人。各人の `topic_count`（その人の発言が出典になった公開済みのトピックの数）。取り込んだ会議録の範囲 `coverage`（最初と最後の会議の日）
- `GET /api/municipalities/{slug}/officials/{id}` — その人と、その人の発言が出典になった公開済みのトピック（新しい会議の順。締め切ったものも）。トピックごとにタグと、その人の引用（引用・会議名・日付・会議録の URL）。`coverage` も
  - 下書きは出さない。別の自治体の議員は 404
- トピックの詳細の `sources` に `official_id`（公人なら。議員のページへのリンクのため）
- 中身の SQL は `records/officials.rs`、API は `interface/api/officials.rs`

### frontend
- タブを3つに: 「トピック｜まちのお金｜議会」。`/{slug}/council`（横フリックで隣のタブへ）
- 議会のタブ: 取り込んだ会議録の範囲の説明と、議員の一覧（名前・役職・任期・トピックの数）。数で並べない（首長、議員は読みの順）
- 議員のページ `/{slug}/council/{id}`: 名前・役職・任期、分野のタグで絞り込むチップ、トピックのカード（タイトル・トピックへのリンク・その人の引用・会議名・日付・会議録へのリンク）
  - 記録が無い人も同じ形で「取り込んだ会議録（範囲）から作ったトピックには、発言が出典として載っていません」
  - 評価・順位・AI の要約・市民の投票の結果は載せない
- トピック詳細の「議会での議論」で、公人の名前を議員のページへのリンクに
- 題と共有したときの表示（`pageMetadata`）

### docs
- api.md・schema.md・overview（画面の表）・data-flow のテーブルの一覧・ADR 0008

### 確かめ
- `cargo test`（一覧・詳細・下書きを出さない・自治体の取り違え（2自治体）・`official_id`）・clippy・fmt
- frontend の lint・型チェック・`npm run build`、本番ビルドで画面を確かめる

## 実装時の変更点
- 役職の表記は、自治体名の最後の字から作る（「市長」「町長」。`lib/officials.ts` の `roleLabel`・`roleTitle`）。自治体を書き込まないため
- 一覧の数は「公開済みのトピック」だけを数える（下書きの出典は数えない）。開発用の DB では、出典に出てくる議員17人のうち、公開済みのトピックに載るのは11人だった
- トピックの詳細の `sources` に `official_id` を返すようにした。会議録の取り込みのテストで「返さない」と確かめていたのを、「公人には付き、職員は null」に改めた（ADR 0008 の決定による）
- 議員のページは自治体のタブの外（`/{slug}/council/{id}`。トピック詳細と同じく、戻るリンクつきの普通のページ）

- 議員のページは、戻るリンクから分野のチップまでを上に固定する（ページのスクロールに sticky で重ねる。入れ子のスクロール枠は作らない）。チップで絞り込むとページの一番上に戻る（2026-10-31 ユーザーの依頼）。敬称は「氏」
