# 予算の歳入の費目の名前を、決算カードの名前にそろえる

## Context
「どこから来たか」を「決算｜予算」で切り替えると、同じものが別の名前で出る。予算は市の資料の名前（AI が資料のとおりに読む）、決算は総務省の決算カードの名前のため。
R6（2024年度）で比べた違い:

| 予算（市の資料） | 決算カード |
|---|---|
| 市税 | 地方税 |
| 市債 | 地方債 |
| 県支出金 | 都道府県支出金 |
| 分担金及び負担金 | 分担金・負担金 |
| 地方特例交付金 | 地方特例交付金等 |
| 環境性能割交付金 | 自動車税環境性能割交付金 |
| 使用料及び手数料 | 使用料 と 手数料（2つに分かれている） |

目的別（款）と性質別は、すでに決算カードの区分にそろえている（`backend/src/budget/mod.rs` の `PURPOSE_KEYS`・`NATURE_KEYS`）。歳入だけが資料のままだった。
**そろえる先は決算カードの名前**にする。全国共通の名前で、ⓘ の説明（`frontend/src/lib/finance-terms.ts` の `REVENUE`）もこの名前で書いてあるため（多自治体の原則にも合う）。

## やること（PR #9 のブランチ `refactor/finances-view` に足す）
1. **抽出の確かめる処理で名前を変える**（`backend/src/budget/mod.rs`）
   - `revenue_key(name) -> String` を足し、`check()` の歳入で、合計の前に名前を変える（同じ名前になったら、いまの「同じ費目は足す」処理で合わさる）
     - 市税・町税・村税・区税 → 地方税、市債・町債・村債・区債 → 地方債
     - 県支出金・都支出金・道支出金・府支出金 → 都道府県支出金
     - 分担金及び負担金 → 分担金・負担金
     - 地方特例交付金 → 地方特例交付金等
     - 環境性能割交付金 → 自動車税環境性能割交付金
     - 使用料及び手数料 → 使用料・手数料（予算の資料は分けていないので、合わせた名前にする。決算は2つのまま）
     - 一覧に無い名前は、そのまま残す（歳入は自治体ごとの費目があり得るので捨てない）
   - 名前を変えたときは、運営者の確認用に notes に出す（性質別と同じ）
2. **取り込み済みの予算も直す**: 新しいマイグレーションで `budget_items`（`category = 'revenue'`）の `item_key` を同じ対応で書き換える（自治体によらない対応なので、どの DB でも正しい。main にマージ済みのマイグレーションは書き換えない）
3. **ⓘ の説明**（`finance-terms.ts`）に「使用料・手数料」を足す（「施設の使用料と、証明書などの手数料。予算の資料では2つを分けていません」）
4. テスト: `tests/budget.rs` に、歳入の名前がそろうこと・合わさること・一覧に無い名前が残ることを足す。実物のテスト（`--ignored`）が通ること
5. ドキュメント: `docs/design/collection.md` の予算の節に、歳入の名前を決算カードにそろえることを書く。計画は `docs/plans/2026-10-28-revenue-keys.md` に保存して最初にコミット

## 確認
- `cargo test`（マイグレーションの適用・seeds のテストを含む）、`cargo test --test budget -- --ignored`、clippy、fmt
- 開発の DB にマイグレーションが当たったあと、R6 の「どこから来たか」を決算と予算で切り替えて、同じ名前で並ぶこと（API で確かめる）
- 那須町・那須烏山市の実物の応答でも、名前の変換が notes に出て、合計の検算が通ること
