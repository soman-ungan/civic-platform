# 「グループごとの特徴」テーブルの表記とハイライトの修正

## Context
ユーザーが `frontend/src/components/voting-panel.tsx` の投票ボタンに 👍️（賛成）・👎️（反対）を付けた（未コミット）。これに合わせて、「グループごとの特徴」のテーブルも次のように直す。
- 表記: 今の「賛成が大きい **%」「反対 **%（小さい）」を、**「👍️ **%」「👎️ **%」の同じ文字サイズ**にする
- 代表意見（Polis の repness）の示し方: 今の「★」を、セルの塗りなどで見やすくする。backend はなるべく変えない

ユーザーの選択: **賛否で色分け**。その意見がそのグループの特徴として「賛成が特に多い」なら緑、「反対が特に多い」なら赤でセルを塗り、該当する行（👍️ か 👎️）を太字にする。自分のグループの列は、塗りではなく青い枠線で囲む（色が重ならないようにするため）。

## backend
**変更しない。** 必要なデータはすでに分析 API にある。
- `groups[].representative[]` の `statement_id` と `repful_for`（`agree` / `disagree`）
- best-agree は API で `agree` に直してある（`backend/src/routes/analysis.rs`）

## frontend の変更（`frontend/src/components/group-table.tsx` のみ）
1. **代表意見の対応表**: 今の `Map<group_id, Set<statement_id>>` を `Map<group_id, Map<statement_id, RepfulFor>>` に変え、セルごとに「特徴なし / 賛成の特徴 / 反対の特徴」を引けるようにする
2. **`VoteCell` の表記**
   - `👍️ {賛成}%` と `👎️ {反対}%` を同じ文字サイズ（`text-sm`）で縦に並べる。色は今と同じ（賛成は緑の文字、反対は赤の文字）
   - 絵文字は `aria-hidden` にし、読み上げ用に「賛成」「反対」の文字を `sr-only` で添える
   - 内訳の帯と人数（`n人`）は残す
3. **代表意見のハイライト**（★ はやめる）
   - 賛成の特徴: セルを淡い緑（`bg-emerald-100` / ダーク `bg-emerald-900/40`）で塗り、👍️ の行を太字にする
   - 反対の特徴: セルを淡い赤（`bg-rose-100` / ダーク `bg-rose-900/40`）で塗り、👎️ の行を太字にする
   - 色だけに頼らないよう、太字に加えて `sr-only` で「このグループの特徴（賛成が多い）」などを添える
4. **自分のグループの列**: 塗り（`bg-sky-50`）をやめ、見出しからその列の最後のセルまでを青い枠線（左右 `border-x-2 border-sky-500`、見出しの上端と最終行の下端も同色）で囲む。見出しの「あなた」バッジは残す
5. **凡例**（表の上の説明文）を書き換える
   - 「👍️ 賛成 / 👎️ 反対の割合」
   - 緑と赤の小さな色見本で「そのグループの特徴（賛成が特に多い / 反対が特に多い）」
   - 「青い枠＝あなたのグループ」
   - 「横にスクロールできます」

ユーザーが変更した `voting-panel.tsx`（👍️👎️）は、そのまま同じコミットに含める。

## 確認
1. `cd frontend && npm run lint && npm run typecheck && npm run build`
2. backend は変更しないので、テストは不要（念のため `cargo test` だけ流す）
3. 開発サーバーで、投票を終えたトピックの「グループごとの特徴」を見る（スマホ幅の見た目はユーザーに確認してもらう）
   - 代表意見のセルが緑か赤で塗られ、該当する行が太字になっている
   - 👍️ と 👎️ が同じ大きさで表示される
   - 自分の列が青い枠で囲まれ、見出しに「あなた」が出ている
   - ダークモードでも読める
4. コミット `feat(frontend): グループごとの特徴の表記とハイライトを改善` → PR #2 に push → CI の成功を確かめる
