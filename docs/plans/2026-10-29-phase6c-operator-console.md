# フェーズ6c: 管理画面とトピックの期限

## Context
運営者の作業（下書きのトピックの確認と公開、確認待ちの意見の採否）は、今は CLI だけでできる。
確認待ちの意見（会議録から公開中のトピックに足した議会の主張など）は、管理画面ができるまで CLI で処理せずに残している。
トピックの期限（ADR 0005。公開から90日、早めに締め切れる、締め切っても結果は読める）は、まだ実装していない。

## 決めたこと（2026-10-29 ユーザーと決定）
- **締め切りは `closes_at` を過ぎたかで決める**。`topics.status` に `closed` は足さない（SQLite では CHECK を変えるのにテーブルの作り直しが要る。期限で自然に締め切れるので定期の処理も要らない）。運営者が早めに締め切るときは `closes_at` を今にする
- **締め切ったトピックの分析は、投票していない人にも見せる**（ロックは投票が全体の傾向に左右されないためのもの。投票が終われば理由がない）
- **市民からのトピックの提案の確認は 6d に回す**（受け付けの仕組みと一緒に作る）

## やること

### 1. トピックの期限と締め切り
- マイグレーション: `topics` に `published_at`・`closes_at`（どちらも ISO8601、NULL 可）
  - 公開したときに `published_at` を今、`closes_at` を90日後にする（CLI の `publish topic` も同じ）
  - いま公開中のトピックは NULL（期限なし）のまま。管理画面で期限を付けられる（日付の計算を両方の DB で動く SQL で書けないため、マイグレーションでは埋めない）
- ルールは `process/progress.rs`: 締め切ったか（`closes_at <= 今`）。締め切ったトピックへの投票・投稿は 409 `topic_closed`。締め切ったトピックの分析はロックしない。次の意見と投稿の条件にも `closed` を出す
- API: トピックの一覧・詳細に `closes_at` と `closed`
- 画面: 一覧と詳細に「あと N 日」か「締め切りました」。締め切ったトピックは投票のカードと投稿の欄を出さず、結果だけ。一覧では締め切ったものを後ろに
- 分析のワーカーは、締め切ったトピックを再計算しない（投票が増えないため）

### 2. 運営者の API（`/api/operator/...`）
- `users.is_operator` の人だけ。ほかの人には 404（あること自体を見せない）
- 投稿者の ID は、運営者の API でも返さない（匿名性）
- 中身は CLI と同じ `records/`・`process/` の関数を使う（ロジックを写さない）。判定の基準は ADR 0007 のまま
- 下書きのトピック: 一覧（タイトル・会議の日・最初の意見・出典の引用・タグ）、詳細、タイトル・説明の編集、意見の追加・編集・削除、タグの付け外し、公開・アーカイブ
- 確認待ちの意見（flagged・pending）: 一覧（トピック・本文・AI の判定の理由・出典の引用）、承認・非公開、pending の AI でのやり直し
- 公開中のトピック: 一覧（期限）、締め切り、期限の変更
- すべて自治体で絞り込む（別の自治体のものは操作できない）

### 3. 管理画面（`/operator`）
- 下書きのトピック・確認待ちの意見・公開中のトピックの3つ。自治体で絞り込む
- 運営者でなければ 404
- スマホでも操作できる

### 4. ドキュメント
- ADR 0005（期限の実装・締め切ったトピックの分析）、CLAUDE.md（API・管理画面）、`docs/cli.md`、`docs/data-flow.md`

## 確認
- `cargo test`（2自治体の seed）
  - 運営者でなければ 404。別の自治体のトピックは操作できない
  - 締め切ったら投票・投稿は 409、分析は誰でも見られる。公開で期限が付く
  - 運営者の API でも投稿者の ID を返さない
- frontend の lint・typecheck・build。手元のブラウザで見てもらう

## しないこと
- 市民からのトピックの提案の確認（6d）
- 運営者の操作の記録（誰がいつ承認したか）。運営者が1人の間は要らない。増えたら考える
- 提言、意見の取りまとめ

## 実装時の変更点
- 判定待ち（pending）の AI でのやり直しは、全件まとめて（`retry_pending`）ではなく1件ずつにした（`POST .../statements/{id}/retry`）。「すべて自治体で絞り込む」に合わせるため。判定の処理は `moderation::retry_one` に切り出し、裏の再判定と共有する。API キーが無ければ 409 `llm_unavailable`（pending を勝手に承認しない）
- 運営者の API は準備中の自治体（`is_active = FALSE`）も扱う（`municipalities::resolve_any`）。公開の前に下書きを用意できるように
- 下書きの意見の削除は、CLI の `remove statement` と同じく非公開（`reject`）にする。API の経路も `.../reject` にまとめた
- 運営者でない人が、ある経路に使えないメソッドを送ると 404 ではなく 405 になる（経路があることは分かるが、ソースは公開するので許容）
- 画面の `/operator` は、運営者でなければ「ページが見つかりません」を出す。ストリーミングが始まったあとのため HTTP の状態は 200（ほかのページの notFound と同じ）。noindex
- 期限の変更は日付で入力し、端末の時刻でその日の 23:59:59 までにする。CLI には期限の変更を足していない（管理画面だけ）
- 運営者にはフッターに「管理画面」のリンクを出す
