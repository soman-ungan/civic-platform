# スマホでの読み込みを軽くする

## Context
Chrome の開発者ツール（CPU 4倍減速・低速4G）で、トピックタブとまちのお金の初めの表示が遅かった（ユーザーの計測。LCP はトピック 4.23s・まちのお金 8.06s。LCP の要素はどちらもサーバーで HTML に入れている文章）。
手元の本番ビルドで測った大きさ（開発用の DB）:

| | API | HTML（生 / gzip） | HTML の要素 | JS（gzip） |
|---|---|---|---|---|
| トピック | `/topics` 28KB（28件。1件約1KB） | 96KB / 19KB | 約400 | 226KB |
| まちのお金 2024年度 | 49KB（うち主な事業163件で 38KB） | 260KB / 37KB | 約1,600 | 235KB |

- まちのお金は、全年度を計算して送ってはいない（細かい内訳は選んだ年度だけ。全年度は推移の分野ごとの合計 4.6KB だけ）。端末のメモリは数MB に収まり、問題ではない
- トピックの一覧は締め切ったトピックも返すので、年を重ねると件数が増え続ける（5年で数百件 → 要素が数万）

2026-10-31 ユーザーと決定。

## やること

### 1. 締め切ったトピックをタイムラインに出さない
締め切ったトピックは合意点のページの「これまでの議論」の地図から開ける。受付中は期限（既定90日）があるので、一覧の件数は頭打ちになる。
- `GET /topics` は受付中（`closes_at` が無いか、まだ来ていない）だけを返す。絞り込みのタグ `tags` も受付中のトピックに付いたものだけ
- 合意点のページへの入口を出すかどうかのため、締め切ったトピックの数 `closed_count` を返す（今は一覧の `closed` から数えている）
- 締め切ったトピックの詳細（`/topics/{id}`）は今までどおり開ける
- docs/design/api.md を直す

### 2. まちのお金の最初の描画を軽くする
- A. カルーセルは、最初は開いている欄だけを描き、ほかの欄は初めて開いたときに描く（一度描いた欄は残し、推移の選び方などは今までどおり保つ）
- C. 最初に開いた欄には切り替えのアニメーション（透明から 220ms）を付けない。切り替えたときだけ
- B（A・C のあとに測って、まだ遅ければ）: 主な事業を別の API に分け、その欄を開いたときに取りに行く

### 確かめ
- `cargo test`・clippy・fmt、frontend の lint・型チェック・`npm run build`
- 本番ビルド（`npm run build` → `npm start`）で、HTML の大きさと要素の数を前と比べる。LCP はユーザーが開発者ツールで測る（開発サーバーは JS が大きく遅いので、本番ビルドで測る）
