# フェーズ6b: 参加の決まり（投稿の条件・上限・分析を開く条件・意見の審査）

## Context
フェーズ6（認証）の2段目。ADR 0005 の「1人を見分けて初めて意味がある」決まりを、6a のアカウント（パスキー）を単位にして動かす。
6a の動作確認で、投稿の審査の問題も見えた（2026-10-28 ユーザーと検討）。
- 投票の前に投稿できてしまう
- 性的な内容（「スケベしたい」）、公人をほめる文（「相馬憲一はいいやつだ」）、進退の要求（「市長には辞任してほしい」）、投票できない文・無関係な文（「わからない」）が通る

決まったこと（2026-10-28）:
- 投稿は、分析を見られるようになってから（最初の意見すべて＋15件に投票した後）
- 次の意見は、最初の意見を先に出す
- 似た意見の判定は AI で行う。重複の投稿は保存しない。ベクトル化や自製の類似度は、後の「意見の取りまとめ」のフェーズで、候補を集める部分として検討する（`process/similarity` のような2段の形にしておく）
- 審査は1回の AI の呼び出しで4つの観点（害・公序良俗／人物／投票できる意見か・トピックとの関係／似た意見）を別々に答えさせる
- 人物の評価・進退・人柄が主の意見は、ほめてもけなしても非公開。政策を議論する場であり、公人の進退はリコールなど正式な手続に委ねる
- 無関係・投票できない文は非公開にして案内を返す（迷ったら公開）
- ADR 0007「意見の審査」を作り、ADR 0003 の「AI に送るもの」を改める
- トピックの期限と締め切りは 6c（管理画面）に回す

## やること

### 1. 参加のルール（`process/progress.rs`。ルールはここだけ）
- `Progress` に最初の意見の数（`seeds_total`）と、そのうち投票した数（`seeds_voted`）を足す
- **分析を見られる**: 最初の意見すべてに投票し、かつ合わせて `min(15, 承認済みの意見の数)` 件に投票した。15 は定数 `ANALYSIS_UNLOCK_VOTES`
  - 残り件数 `analysis_remaining` = max(未投票の最初の意見の数, 必要数 − 投票数)。API の `progress` に入れ、`/analysis` の `locked` もこの数にする
  - タイムラインの合意点（`/consensus`）も同じ条件にする
- **投稿できる**（`can_post`）: パスキーを登録している・分析を見られる・そのトピックの自分の意見が上限（1件）未満
  - 数えるのは pending・flagged・approved。rejected は数えない（書き直して出し直せる）。最初の意見（投稿者なし）は数えない
  - 市民提案のトピックの「提案した本人は3件」は 6d
- 参加の状態 `completed`（すべてに投票した）は今のまま

### 2. 次の意見（`/next-statement`）
- 投票していない最初の意見があれば、その中から選ぶ（Polis の優先度で重み付け）。無ければ今までどおり全体から
- Polis との違いとして `docs/polis-math.md` に書く

### 3. 投稿の API
- 投稿できなければ: 未登録は 401 `registration_required`（今のまま）、分析がまだなら 403 `votes_required`、上限なら 409 `statement_limit`
- トピックの詳細に `can_post` を足す
- 判定の結果に `duplicate` を足す。重複なら保存せず、`similar: {id, body}` を返す
- 非公開のとき、理由の種類 `rejection`（`harm` / `person` / `official_name` / `not_votable`）を返す。理由の文（運営者向け）は今までどおり返さない

### 4. 意見の審査（`process/moderation.rs` を広げる）
- **公人の氏名の確かめ（AI を使わない）**: その自治体の `public_officials` の氏名（空白を除いて）が本文にそのまま含まれていたら、AI に送る前に非公開（`official_name`）。名字だけは見ない（地名などと重なるため。AI の「人物」に任せる）
- **AI に送るもの**: 本文、トピックのタイトルと説明、そのトピックの承認済みの意見（番号を振った本文。新しい順に最大300件。超えたら警告をログに出す）。参加者の ID・関わり方は送らない
- **答えさせるもの**（構造化出力）: `harm`（ok / reject / unsure）、`person`（ok / reject / unsure）、`votable`（ok / reject）、`duplicate_of`（同じ意見の番号。無ければ 0）、`reason`、`suggestion`
- **まとめ方**: reject があれば非公開（害 → 人物 → 投票できない の順に理由を選ぶ）→ unsure があれば確認待ち → 重複なら案内 → それ以外は公開
- 害・公序良俗の基準に、性的な内容・違法な行為をすすめるもの・自分や他人を傷つけることをすすめるもの・宣伝やスパムを足す
- 人物: 特定の人物の評価・進退・人柄が主のものは非公開（ほめても同じ。役職名で特定できるものも）。政策・公務・議会での発言への賛否、役職や制度そのものへの意見は公開
- 投票できる意見か: 賛成・反対のしようがない文（「わからない」、質問だけ、単語だけ）と、トピックとはっきり無関係なものは非公開。少しでも関係すれば公開、迷ったら公開
- 判定できないとき（キーが無い・通信の失敗・費用の上限）は今までどおり。キーが無ければ承認（重複の判定はしない）、失敗は pending。refusal は flagged
- pending の再判定も、同じ文脈（トピックと意見）で判定する。再判定で重複と分かったら rejected にし、理由に元の意見を残す（案内はもうできないため）
- 会議録の最初の意見の審査は、トピック（下書き）のタイトルと説明を渡し、意見の一覧は渡さない（重複は取り込みの側で見ている）
- モデル: 今の `MODERATION_MODEL`（既定 Sonnet 5.5）をそのまま使う

### 5. frontend
- 投稿のボタン: `can_post` が無いときは理由を出す（「分析が見られるようになったら投稿できます（あと N 件）」「このトピックには投稿済みです（1トピック1件まで）」）。未登録なら今のパスキーの案内
- 進み具合の横に「分析まであと N 件」
- 重複: 「同じ意見がすでにあります」と、その意見をその場で賛成・反対・パスできるボタン（投票は上書きできるので、投票済みでもよい）
- 非公開の理由ごとの案内（人物 → 政策や事業についての意見にする、投票できない → 賛成・反対できる1つの意見にする／迷ったらパス、など）と、書き直しの例

### 6. 評価
- `evals/moderation.jsonl` に、トピック（`topic`）と既存の意見（`statements`）を持てるようにし、`expected` に `duplicate` と理由（`rejection`）を足す
- 足すケース: 性的な内容、公人（架空の名前）をほめる・けなす、役職名での進退の要求、政策への批判（公開）、「わからない」、質問だけ、無関係、少しだけ関係する提案（公開）、同じ意見（重複）、立場が逆の似た意見（公開）
- 実際の API を呼ぶので、`eval moderation` を走らせる前にユーザーの了承を得る

### 7. ドキュメント
- ADR 0007「意見の審査」（新規）。ADR 0003 の「AI に送るのは本文だけ」を改める注記、ADR 0005 に実装の場所
- CLAUDE.md（分析の条件・投稿の条件・審査・API）、`docs/polis-math.md`（最初の意見を先に出す）、`evals/README.md`

## 確認
- `cargo test`（2自治体の seed。偽の LLM）
  - 分析: 最初の意見が残ると開かない、15件で開く、意見が15件より少なければ全部で開く、残り件数
  - 次の意見: 最初の意見が先に出る
  - 投稿: 分析の前は 403、2件目は 409、rejected のあとは出し直せる、最初の意見は数えない
  - 審査: 公人の氏名は AI を呼ばずに非公開、観点ごとの答えのまとめ方、重複は保存せず上限にも数えない、別のトピックの意見とは比べない、AI に参加者の ID を送らない、再判定で重複なら rejected
- frontend の lint・typecheck・build。手元のブラウザで見てもらう
- 評価（費用がかかるので、了承を得てから）

## しないこと
- 市民提案のトピックの3件（6d）、管理画面・トピックの期限と締め切り（6c）
- 候補を集める部分のベクトル化・自製の類似度（意見の取りまとめのフェーズ）

## 実装時の変更点
- **投稿できるかは、トピックの詳細ではなく次の意見の応答（`posting`）で返す**: 投票のたびに変わり、画面は投票のたびに次の意見を読み直すため。`can_post` の真偽ではなく、理由（`status`）と残り件数を返す（画面の案内に使う）
- **分析の前の投稿は 403（`votes_required`）**: 401 はパスキーの登録、409 は上限に使う
- **重複のときは 200**（保存しないので 201 ではない）。応答に新しい意見の ID は無い
- **新しい環境変数は作らない**: 審査は今の `MODERATION_MODEL` のまま（`.env.example` は変えない）
- **プロンプトキャッシュに乗るのは審査の基準（system）だけ**: トピックと意見は呼び出しごとの入力に入れた。トピックの部分もキャッシュするには、入力を複数のブロックに分ける改修が要るので、費用を見てから考える
- **似た意見の判定に渡す意見は、番号で渡す**（ID を送らず、範囲外の番号は重複ではないとみなす）
- **評価データの既存の4件の正解を、新しい基準に合わせて直した**: m028「なんとなく賛成です。」と m029（話題から外れた文。トピックを付けた）は not_votable、m054（市長への皮肉）と m055（議員の親戚の疑惑）は rejected（人物）
- **フロントの投票ボタンを共通にした**（`components/participation/vote-buttons.ts`。投票カードと似た意見の案内で使う）
- **票はあとから変えられないようにした**（2026-10-29 ユーザーと決定）: 動作確認で、似た意見の案内から投票済みの意見にもう一度投票できた（投票の API が上書きを受け付けていた。フェーズ2の「最後の判断で上書き」）。投稿できるのは分析を見たあとなので、分析を見てから票を合わせ直せてしまう。投票済みの意見への投票は 409 `already_voted` にし、案内には、その人の票（`your_vote`）を返して投票のボタンを出さない

- **評価の結果（2026-10-29、claude-sonnet-5-5、80件）**: 1回目は 77/80（見逃し・行き過ぎは 0）。外れた3件はすべて正解を flagged にしていたケース。m056（私人への当てこすり）と m059（職員の氏名を挙げた苦情）は、新しい基準では非公開が正しいので正解を rejected に直した。m058（自治会長の会計への疑い）は公開されたので、審査の基準の「害」の unsure に「特定できる私人の不正を疑い、説明や責任を求めるもの」を足した。2回目は 80/80。費用は1回 $0.14
