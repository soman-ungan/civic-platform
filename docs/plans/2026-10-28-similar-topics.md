# 会議録の取り込みで、似たトピックと意見の少ないトピックを扱う

## Context
会議録を何日分も取り込むと、同じ定例会の中（同じ論点を何人もの議員が質問する）や、前の定例会と、同じ論点のトピックができる。
また、最初の意見が3件未満のトピックは、今は捨てている。
ユーザーと決めたこと（2026-10-28）:
- **似ているかの基準**: 同じ自治体で「何を決める・変えるか」が同じ。立場や言い回しでは判断しない
- **似ていたら**: 新しい意見を足す。公開中のトピックに足す意見は、最初の意見として扱わない
- **意見の少ないトピック**: 捨てずに残し、運営者の承認を待つ。反対の立場の意見を AI で作る案は、原則（ADR 0004「AI に新しい選択肢を作らせない」）とぶつかり、改修も増えるので見送る（ユーザーの条件どおり）
- **類似度の判定のしかた**（ベクトル検索など）は、後のフェーズ（意見の取りまとめ）で決める。今は既存のトピックの一覧との読み比べだけ

## やること
1. **似たトピックの印**: 取り込みの指示文に、その自治体の公開中・下書きのトピックの一覧（id・題・説明）を足す。出力の形に任意の `same_as`（同じ論点の既存のトピックの id）を足す。一覧に無い id は印を無視し、捨てたものとして知らせる
2. **印が付いたときの扱い**
   - 下書きへの印: 1つにまとめる。意見は最初の意見として、出典の引用（`topic_sources`）もそのトピックに足す
   - 公開中のトピックへの印: 新しいトピックは作らない。意見をモデレーションに通し、非公開以外を確認待ち（flagged。理由に「議会の新しい主張」）で足す。根拠は `statement_sources` に記録する。公開中の画面の出典（`topic_sources`）は足さない（運営者の確認を経ずに画面が変わらないように）
   - 締め切ったトピック（新しいトピックとして作り、前のトピックへのリンク）は、まだ締め切ったものが無いので今回は作らない
3. **最初の意見かどうか**: マイグレーションで `statements.is_seed` を足す（今の意見は `user_id IS NULL` を最初の意見として埋める）。今の分析の条件（すべての意見に投票）は変えない。フェーズ6で「最初の意見すべて＋15件」にするときに使う
4. **意見の少ないトピック**: 最初の意見が1〜2件でも捨てずに下書きにし、「意見が少ない（N件）」と注記する。0件は捨てる
5. **ドキュメント**: ADR 0005、`docs/cli.md`、`.claude/commands/import-minutes.md`、CLAUDE.md

## 確認
- `cargo test`・clippy・fmt。テストを足す: 下書きへの印でまとまる、公開中への印で確認待ちに足される（`is_seed` は false、`topic_sources` は増えない）、一覧に無い印は無視される、意見が1〜2件のトピックが残る
- マイグレーションで既存の意見の `is_seed` が埋まる（`tests/seeds.rs`・PostgreSQL 互換の CI）
- そのあと、残りの4日分を新しい形で取り込む（印の判断はユーザーに見せる）
