# 資料の取り込みを「AI との共同作業」でもできるようにする（API を使わない取り込み）

## Context
ユーザーの相談（2026-10-28）: 会議録・予算・決算の取り込みは、いまは LLM の API を通している。資料の更新は年に数回なので、サーバー管理者が CLI で投入する手段もほしい。要約などの LLM の作業は、API ではなく、Claude Code での共同作業（いまのこの作業のような形）でもできるのでは。現状・実機での使い方・管理コスト（費用と手間）から検討する。

## 現状の分析
| 資料 | 取得 | LLM | 費用（大田原市1市・1年） | 更新の頻度 |
|---|---|---|---|---|
| 決算カード | `collect run`（総務省の Excel を自動で取得） | **使っていない**（決まった形の表を読むだけ） | 0 | 年1回 |
| 当初予算の概要 | `collect run --source`（自動）か、手で取った PDF を `import budget` | API で PDF を読む（款別・性質別・歳入・主な事業） | 約 0.8 ドル | 年1回（2〜3月） |
| 会議録 | **手でコピー**して `import minutes`（規約のため自動で取らない） | API でトピックの下書きを作る | 1日分 0.3〜0.4 ドル × 年12〜20日 ≒ 5〜8 ドル | 年4回の定例会のあと |
| （参考）投稿のモデレーション・タグ付け | — | API（その場で判定） | 1日の上限 1 ドル（実際はずっと少ない） | 投稿のたび |

- **決算カードは、すでに API を使っていない。** 変える必要はない
- 予算と会議録は、コードが「AI に読ませる部分」と「確かめて保存する部分」に分かれている（`budget::schema()`・`budget::check()`、`minutes::extract::schema()`・`minutes::extract::check()`）。確かめる部分（合計の検算、名前と金額が本文にあるか、引用が原文どおりか、氏名が入っていないか）はプログラムなので、**AI の出力をどこから持ってきても同じ検査を通せる**
- **投稿のモデレーションは API のまま残す必要がある。** 市民の投稿をその場で判定するので、人が手を介せない（API キーが無いと全件承認になり、本番では使えない）。費用は小さい

## 費用と手間の比べ（1市・1年）
| | API で取り込む（いま） | 共同作業で取り込む（案） |
|---|---|---|
| 取り込みの費用 | 予算 約1ドル＋会議録 約5〜8ドル。自治体が増えるとその倍数（10市で 60〜90 ドル） | 追加の費用なし（Claude Code の契約の範囲。使う量は契約の上限の内側） |
| 管理者の手間 | コマンド1つ（数分）＋下書きの確認 | 共同作業（1日分で10〜20分）＋下書きの確認 |
| いちばん重い手間 | **下書きの確認**（どちらでも同じ。ADR 0004 で人が確かめると決めている） | 同じ |
| 自動化 | 収集から下書きまで、定期の実行にできる | 人がいる時にしかできない |
| 品質の担保 | 同じ検査（check）を通る | 同じ検査を通る。加えて、作業中に人が原本と見比べられる |
| 記録 | `llm_usage` にモデル・費用 | 取り込みの記録に「共同作業」と残す（どの方法で作ったか分かるように） |

**結論（提案）**: 両方の道を残す。小さな自治体数のうち（いま〜展開の初め）は、年に数回の取り込みを**共同作業で行うのを基本**にし、API は自動化したくなったとき（自治体が増えたとき）の道として残す。決算カードは今のまま。モデレーションは API のまま。

## 実機での管理者の使い方（イメージ）
本番のサーバー（フェーズ7で決める。Docker で backend を動かす想定）と、管理者の手元のパソコン（リポジトリと Claude Code がある）の2か所で作業する。
1. **手元で準備**: 原本（会議録のテキスト・予算の PDF）を `data/private/` に置き、`cargo run -- import minutes ... --dry-run`（いまと同じ。発言者・名簿の確認）
2. **手元で共同作業**: Claude Code で「この会議録の取り込みをしよう」と頼む。Claude が新しいコマンドで指示文・出力の形・入力を書き出し、原本を読んで、決まった形の JSON（`data/private/extractions/…json`）を作る。人はその場で原本と見比べ、気になる点を直させる
3. **手元で検査**: `import minutes ... --extraction <json> --dry-run` で、API の時と同じ検査を通し、捨てられたもの・直したものを見る
4. **本番に投入**: 原本と JSON をサーバーに送り（scp など）、サーバーで `import ... --extraction <json>`（検査をもう一度通して下書きを保存）→ `topics show` / `budget show` で確かめて `publish`
   - サーバーには API キーを置かなくても取り込める（キーはモデレーションのためだけ）
5. 年のカレンダー: 2〜3月 予算 / 定例会（3・6・9・12月）の会議録の公開のあと 会議録 / 決算カードの公表のあと `collect run`

## やること（実装する場合）
1. **指示文と入力を書き出すコマンド**: `cargo run -- extraction prompt minutes|budget --municipality <slug> --file <原本> [...]`
   - 会議録: いまの API に渡しているものと同じ（指示文 `minutes::extract` の SYSTEM_PROMPT・出力の形 `schema()`・`build_input()` で作った発言の一覧・名簿）
   - 予算: 指示文・`schema()`・分野の語彙。PDF は Claude Code が直接読む
   - 書き出し先は `data/private/extractions/`（git の管理外）
2. **AI の出力を受け取る取り込み**: `import minutes|budget ... --extraction <json>`
   - API を呼ばず、同じ `check()` と保存の処理を通す（`minutes::import`・`budget::extract` の中の、API を呼ぶ部分だけを差し替えられる形にする）
   - 予算の検査は PDF の本文（`pdftotext`）が要るので、`--file` も今までどおり渡す
   - 取り込みの記録（`documents`）に、作り方（`api` / `manual`）を残す（新しいマイグレーション）
3. **共同作業の手順をリポジトリに置く**: `.claude/commands/import-minutes.md`・`import-budget.md`（Claude Code の手順。公開リポジトリなので、誰でも同じやり方で再現できる）
4. **ドキュメント**: `docs/cli.md` に「共同作業で取り込む」の流れ、`docs/design/collection.md` に方針（API と共同作業の2つの道、モデレーションは API のまま）
5. テスト: 保存してある実物の応答（`data/private/budget/*-extraction.json` など）を `--extraction` で取り込めること、API の時と同じ結果になること

## 確認
- `cargo test`・clippy・fmt
- 実物で: 大田原市の R8 予算の保存済みの応答を `--extraction` で `--dry-run` し、API の時と同じ 165 件・検算が通ること
- 会議録 1日分を、Claude Code との共同作業で JSON にし、`--extraction` で下書きを作って、API の時の下書きと見比べる（ユーザーと一緒に）
