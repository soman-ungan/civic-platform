# 合意点のページ（「これまでの議論」をタブから「みんなの合意点」へ移す）

## Context
トピックマップと市民のまとめ（`2026-10-30-topic-map.md`、PR #30 で未マージ）で、タブ「これまでの議論」を足した。
ユーザーと見直し、合意に関わるものを1か所にそろえるため、タイムラインの「みんなの合意点」を入口にしたページへ移す（2026-10-30。案A）。

## 決めたこと（2026-10-30 ユーザーと決定）
- `/{slug}/consensus`: 上に合意点の一覧、下に「これまでの議論」（地図 → まとめ → 提案）。スクロールはページだけ
- タブは「トピック・まちのお金」の2つに戻す（`/{slug}/map` は main に入っていないので消すだけ）
- タイムラインの「みんなの合意点」の欄は、このページへの入口にする。合意点が0件でも、締め切ったトピックがあれば出す
- 合意点をタップすると: 元のトピックが締め切ったものなら、同じページの地図でそのトピックを起点にして示す（`?focus=`。地図の分野は、そのトピックのタグのうち締め切ったトピックの多い分野タグを backend が選ぶ）。受付中なら今どおりトピックの画面へ。一覧には「地図で見る」「トピックへ」の印を付ける
- 受付中のトピックは地図に載せない（まとめを作れるのは締め切ったトピックだけなので、押せない点が混ざって分かりにくくなる）
- このページでは、締め切ったトピックの合意点は投票を問わず誰にでも出す（締め切ったトピックの分析は誰にでも見せる決まり。ADR 0005）。受付中のトピックは今の決まり（本人が投票し終えたものだけ）
- PR #30 に足す

## やること
1. backend: 合意点の API（`GET /municipalities/{slug}/consensus`）に `include_closed`（締め切ったトピックは投票を問わず出す）と、各件に `closed` を足す。地図の API に `focus`（タグが無いとき、そのトピックの分野タグを選ぶ）
2. frontend: `/{slug}/consensus` のページ（合意点の一覧と地図。`focus` で起点を決めて開く）。タブを2つに戻し `/{slug}/map` を消す。タイムラインの欄を入口に。まとめの「←」をこのページへ
3. テストと docs（ADR 0005・api・overview・計画の記録）
