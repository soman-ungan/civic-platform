# はじめての人への使い方（チュートリアル）と、例の分析

## Context
2026-11-20、ユーザーの要望。公開して間もなく参加者が少ないので、本物のトピックの分析（意見グループ・合意点）は
まだ出ない（2人以上がそれぞれ7件以上に投票し、グループごとの数字は5人以上で出る）。
初めて来た人が、投票すると何が見られるのかを分からないまま帰ってしまう。

例題のトピックを本番の DB に入れる案は採らない。架空の票が本物の市民の意見と同じ画面・数字
（合意点のページ・トピックマップ・まとめ）に混ざり、行政の透明性を掲げるサービスとして避けたいため。
混ざらないようにする印や除外を backend に足すより、例を画面の中だけに閉じ込めるほうが単純で確実。

## やること
1. **使い方のページ `/guide`**（自治体によらない。`/about` と同じ並び）
   - 架空の例題トピック（どの自治体にもありそうな論点。【例】と明記）を使って、流れを順に見せる
     1. 議会で出た論点がトピックになる（最初の意見は議会で出た主張）
     2. 意見に「賛成・反対・パス」で投票する。**例の意見に実際に投票してみられる**（票は画面の中だけ。どこにも送らない）
     3. 最初の意見すべてに投票すると「みんなの意見」が開く。例の分析を、**本物の分析画面と同じ部品**
        （`components/analysis/` の意見マップ・グループごとの特徴・グループの構成・関わり方ごとの違い）で見せる
     4. 自分の意見を出す・トピックを提案する・締め切ったトピックをまとめる（パスキーが要ることも）
   - 例の分析の上に「架空の例です。実際の投票ではありません」と出す
   - 最後に「はじめる」で、来た自治体のトップに戻る（`?from=<slug>`。無ければ `/`）
2. **初めて開いたときに出す**: 自治体のトップ（タブの画面）を、その端末で初めて開いたときに `/guide` を開く
   - 印は localStorage（`cp_guide_seen`）だけ。サーバーには何も残さない。使えないとき（ブラウザの設定など）は出さない（毎回出さないように）
   - 共有されたトピックの URL から直接来た人には出さない（読みたいものを邪魔しない）。その日に初めてのときのカバーとは別
   - プライバシーポリシーの「ブラウザの中に置く印」に足す
3. **あとから開ける**: 「このサービスについて」の「できること」の下にリンク。フッターは今の2つのまま
4. **例のデータ**: 本物のアルゴリズムで計算した分析の結果を、固定の JSON として frontend に置く
   - `scripts/generate_tutorial_example.py`: 例題のトピックと架空の参加者・票の SQL を出す（乱数のシード固定）。
     手元の使い捨ての DB に入れて分析し、API の応答を取って ID を置き換えた JSON を出す（手順はスクリプトの説明に書く）
   - あなたの位置（`map.you`）は出さない（使い方のページの票と合わないため）
   - 関わり方の分布は開発用サンプルと同じ考え方（どの区分も5人以上）

## 守ること
- 本物のデータ・API に触れない（例の票は送らない。分析の JSON は静的）
- 人を属性で分けない（ADR 0002）。例でも、分けて見せるのは関わり方だけ
- コメント欄は作らない

## 確かめ
- lint・型チェック・ビルド。スマホの幅で、初めて開いたとき `/guide` が出る・2回目は出ない・投票してみると例の分析が開く・「はじめる」で戻る
- 例の JSON が今の `AnalysisView` の型に合う（型チェック）
