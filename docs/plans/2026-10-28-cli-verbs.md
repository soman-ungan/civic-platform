# CLI の整理: 動詞が先の形と、段階ごとの分類

## Context
今の CLI は、動詞が先のもの（`import budget`・`extraction prompt`・`eval`）と名詞が先のもの（`budget show`・`topics publish`）が混ざっている。対象の指し方（位置か `--municipality` か）、単数か複数かもそろっていない。
ユーザーの方針（2026-10-28）は次の2つ。
- 形を `<動詞> <対象> [オプション]` にし、機能を段階ごとに分ける
- その対象には要らない処理は、何もせずに通す（メッセージを出して終了コード 0）

**分類は 2026-10-28 に確定。** 原本の扱い・意見の承認の扱い・オプションの細部は、分類が決まってから相談する。

## 分類（確定。ユーザーの案に、抜けていたものを足した）
「無」は何もせずに通す組み合わせ。★はユーザーの案に足したもの。

### 1. 資料を DB に入れる（fetch / extract / import）
| | settlement（決算カード） | budget（予算の概要） | minutes（会議録） |
|---|---|---|---|
| `fetch` | 総務省から取得 | 市のサイトから取得 | 無（規約のため、手でコピー） |
| `extract` | 無（AI を使わない） | AI で読み、JSON にする | 同じ |
| `import` | Excel を読んで保存 | JSON を検査し、下書きに保存 | 同じ |

- 原本の中身を確かめるだけの処理は、この段階の `--dry-run` にする（DB を読まないので、段階2の `show` にはしない）
  - `extract minutes --dry-run`: AI を呼ばずに、発言者・名簿に無い人・議事日程を出す（今の `import minutes --dry-run`）
  - `import <対象> --dry-run`: 検査だけして、保存しない
- 共同作業: `extract <対象> --manual` で指示文を書き出す（今の `extraction prompt`）。`import` は、API で作った JSON も共同作業で作った JSON も同じように受け取る

### 2. DB を見る・直す（show / list / edit / add / remove ★publish / ★archive）
対象はテーブルではなく、画面やドキュメントで使っている「まとまり」にする。

| 対象 | 中身（テーブル） |
|---|---|
| budget | `budgets`・`budget_items`・`budget_projects` |
| settlement | `settlement_items`・`municipality_stats` |
| minutes | 取り込んだ会議録（`documents`）と、そこから作ったトピック |
| topic | `topics`・`topic_sources`・`topic_tags` |
| statement | `statements` |
| ★tag | `tags`（語彙）と、トピックに付けたタグ |
| ★source | `collector_sources`（収集先。今の `collect list`） |

| | budget | settlement | minutes | topic | statement | tag | source |
|---|---|---|---|---|---|---|---|
| `list` | ○ | ○ | ○ | ○（`--drafts`） | ○（`--status`。今の `moderation list`） | ○（語彙。`add tag` に使う ID を見る） | ○ |
| `show` | ○ | ○ | ○（作ったトピック） | ○ | ○ | 無 | ○ |
| `edit` | 無 | 無 | 無 | ○（タイトル・説明） | ○（投票の無い意見の本文） | 無 | 無 |
| `add` / `remove` | 無 | 無 | 無 | 無 | ○（トピックの最初の意見） | ○（トピックにタグを付ける・外す） | 無 |
| ★`publish` / `archive` | ○ | 無（取り込んだら公開） | 無（トピックごとに） | ○ | 保留（下の「あとで決めること」） | 無 | 無 |

- ★`publish` / `archive` は、下書きを公開する・取り下げる「状態の編集」なので、この段階に入れる

### 3. DB の中身を判定・計算する（moderate / analyze ★classify）
この3つは、API サーバーが裏で自動で動かしている処理と同じもの。コマンドは、それを今すぐ手で動かすためにある。

| | topic | statement |
|---|---|---|
| `moderate` | 無（市民からのトピックの提案ができたら、ここで判定する。ADR 0005） | 判定待ちを AI で判定し直す（今の `moderation retry`） |
| ★`classify` | AI で分野・地区のタグを付ける（今の `tag`） | 無 |
| `analyze` | 意見マップ・グループ・合意点を計算する | 無 |

- ★`classify` をこの段階に入れる理由: `moderate` と同じく、DB の中身を AI が判定する処理で、サーバーが裏で動かしている。市民から提案されたトピックにも使う
- 動詞を `tag` にしないのは、段階2の対象の `tag`（`add tag` で手で付ける）と名前がぶつかるため（ユーザーと決めた）

### 4. ★準備と保守（どの段階にも入らないもの）
| コマンド | すること |
|---|---|
| （引数なし） | API サーバーを起動する |
| `seed [--dev]` | リポジトリの seed（マスタ・サンプル）を入れる。行政の資料ではないので、段階1には入れない |
| `eval moderation\|tagging` | AI の精度を測る。DB を変えない |

## 決めたこと（2026-10-28。ユーザーの了承済み）
1. **原本**: `fetch` は `data/private/fetched/<slug>/<対象>/`（git の管理外）に原本と記録（`<名前>.meta.json`）を置き、`import` が済んだら消す（`--keep` で残す）。手でコピーした原本は消さない（今までどおり `data/private/` に置き、手で消す）。「処理が終わったら原本は捨てる」（collection.md）は保つ
2. **意見の承認・非公開**: 段階3の `moderate statement --id X --approve|--reject`（人の判定も AI の判定も「判定」）。確認待ちの一覧は `list statement --status flagged`。`publish|archive statement` は何もせずに通し、`moderate` を案内する
3. **どれを指すか**: すべてオプション。どの動詞でも同じ名前（`-m/--municipality`・`-y/--year`・`--id`・`--file`・`--topic`・`--dry-run`・`--again`・`--force`）。位置で指す形は作らない
4. **順番**: PR #12 の上で行う。会議録1日分の試しは新しいコマンドで1回。マージは #12 → この PR

## 実装
### 動詞と対象の決まり
- 段階ごとに対象の型を分ける（段階1は settlement・budget・minutes、段階2は7つ、段階3は topic・statement）。段階に無い対象は clap が弾く（`--help` に出る対象も段階ごとになる）
- 段階の中で要らない組み合わせは「〜は〜しないので、何もしません」と出して終了コード 0
- 対象に要るオプションが無いとき（`show topic` に `--id` が無いなど）はエラー

### 段階1: fetch / extract / import のつなぎ方
- 3つのコマンドは、原本の隣の `<名前>.meta.json` でつなぐ。中身: 取得元の URL・収集先・年度・条件付き取得の記録（`CacheEntry`）・会議名と開催日・AI の出力の作り方（api / manual）
  - `fetch` が書く（取得の記録）。`extract` が足す（会議名・開催日・作り方）。`import` が読む（`--url` などを毎回打たなくてよい。オプションを渡せば、そちらが優先）
  - `fetch_cache` に記録する（`fetch::remember`）のは、今までどおり保存が済んだあと（`import` の中）。失敗したら次の `fetch` でもう一度取る
- `extract` は AI の出力（JSON）を `<名前>.extraction.json` に書き、検査の結果も出す（保存はしない）
  - API で作ったものは meta に `extraction: api`、共同作業（`--manual` で指示文を書き出し、Claude Code が JSON を作る）は `manual`。`documents.extraction` にそのまま入る
- `import` は JSON だけを受け取り、API を呼ばない（費用がかかるのは `extract` だけになる）
- ライブラリ:
  - `collect`: `Collector::collect` を `fetch`（取得して置き場に書く）にし、決算カードの読み取りと保存は `settlement_card::import` に分ける。決算カードの `fetch` は、どの Excel にその自治体のシートがあるかまでを見る（取る原本を1つに決めるため）。予算の `fetch` は AI を使わなくなる（`--ai` は無くなる）
  - 原本の置き場: `collect::store`（パス・meta の読み書き・消す）。置き場の根は `PRIVATE_DIR`（既定 `../data/private`）
  - `minutes`・`budget`: API を呼んで JSON を返す関数を公開する（今の `raw_output` と `extract` の API の部分）。`Extraction` に「API で作って保存した JSON」を足す（作り方は api のまま残す）

### CLI のファイル
- `src/cli/` を段階ごとに: `ingest.rs`（段階1）・`records.rs`（段階2）・`process.rs`（段階3）・`eval.rs`・`mod.rs`（`seed`・共通のオプション・対象の型）
- 今の `budget.rs`・`collect.rs`・`extraction.rs`・`import.rs`・`moderation.rs`・`topics.rs` は無くなる

### 新しく作る一覧
今のコマンドに無かったものだけ（段階2の表の ○ のうち）: `list settlement`（年度・人口）、`list minutes`（取り込んだ会議録と、作ったトピックの数）、`list topic`（公開済みも。`--drafts` で下書きだけ）、`list tag`（分野の語彙とその自治体の地区）、`show settlement`、`show minutes`、`show statement`、`show source`

### ドキュメント
`docs/cli.md`（書き直す）・`docs/data-flow.md`・`docs/design/collection.md`（原本の置き場）・CLAUDE.md（よく使うコマンド）・`.claude/commands/import-*.md`・`.env.example`（`PRIVATE_DIR`）

## 実装時の変更点
- **`fetch_cache` に記録する時期の例外**: 決算カードの `fetch` は、その自治体のシートが無い Excel（同じ県のほかの Excel）を、その場で記録する（置き場に置かないので、`import` が記録する機会が無いため。前と同じ動き）
- **公開済みの予算の確認は `fetch` に残した**: 公開済みの年度の資料が更新されていたら、取得しない（警告を出す）。前は取得してから捨てていた
- **`import settlement` は `-m` が無ければ、置き場のすべての自治体を処理する**（`fetch settlement` を `-m` なしで動かしたあとに続けられるように）
- **`import` の `--extraction` で原本の隣以外の場所から渡した出力は、共同作業（manual）とみなす**。原本の隣のものは、`extract` が記録した作り方（api / manual）をそのまま `documents.extraction` に入れる
- **`extract budget --dry-run`** は、PDF のページ数と文字数を出す（AI を呼ばない）
- **`list statement`** は、状態もトピックも指定しなければ、前の `moderation list` と同じ出力（確認待ち）。`show statement` は投稿者を出さない（最初の意見か市民の投稿かだけ）
- **前と後の出力の比べ**: 使い捨ての DB（`seed --dev` と実物の R8 予算の共同作業の JSON）で、`list budget`・`show budget`・`list topic --drafts`・`show topic`・`list source`・`list statement`・`import budget` の出力が、次の行の案内（新しいコマンド名）を除いて前と同じこと、取り込んだ予算の行（`budget_items`・`budget_projects`・`documents`）が同じことを確かめた
- **決算カードの fetch → import は、実物のデータが要るテスト（`#[ignore]`。`data/private/soumu/`）でしか確かめていない**。手元に実物が無いので、今回は動かせていない。実物（ネットワーク）での確認は、ユーザーの了承を得てから行う
- **確認中に、実際の API を1回呼んでしまった**: `extract minutes`（`--manual`・`--dry-run` なし）を、ルートの `.env` に API キーがある状態で動かした（会議録1日分。推定 0.40 ドル。記録は使い捨ての DB の `llm_usage`）。ユーザーの了承を得ずに呼んだ。以降の確認は `ANTHROPIC_API_KEY=""` で行い、`tests/cli.rs` も API キーを空にして動かす
