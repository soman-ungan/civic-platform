# デプロイをリリース直前にまとめる方針への変更

## Context
ステージングのデプロイ基盤の計画を出したところ、ユーザーから「全体の機能がそろってから、デプロイ先の選定・契約とデプロイ作業をリリース直前にまとめて行いたい」と方針の変更があった。

これは ADR 0001（「フェーズ2の完了後にステージング」）と、CLAUDE.md の開発フェーズの記述と食い違うので、ドキュメントを新しい方針に合わせる。コードやインフラの変更はない。

影響の整理:
- 本番の公開は認証（フェーズ6）の後なので、ステージングがなくても公開前の判断には影響しない
- PostgreSQL 互換の確認は、CI で毎回行われる（ADR 0001 の第1段階は実施済み）
- スマホ実機での確認は、同じ LAN 内から開発サーバーにつないで行える
- 代わりに、本番特有の問題（HTTPS、Cookie の Secure 属性、イメージ化、バックアップ）はリリース準備のときにまとめて出てくる。準備の期間を長めに見ておく

## 変更内容（1コミット: `docs: デプロイをリリース直前にまとめる方針に変更`）
`main` で直接作業する（ドキュメントだけの変更なので、ブランチと PR は使わない）。

1. **`docs/adr/0001-docker-adoption.md`** の末尾に「改訂（2026-10-26）」の節を足す。元の本文は経緯として残す
   - 導入のタイミングを「フェーズ2の完了後にステージング」から「リリース準備のときに、デプロイ先の選定・契約とまとめて行う」に変更したこと。理由はユーザーの判断（機能がそろってから選びたい）
   - Docker を導入する範囲（本番と CI だけで、開発環境はコンテナ化しない）は変えない。CI の PostgreSQL 互換チェックは実施済み
   - **参考: 2026-10 時点のデプロイ先の調査**（比較表と出典。契約の前に料金を改めて確認すること）
     - さくらのVPS 2GB: 石狩 1,738円 / 東京 1,958円（月払い、最低3か月）
     - ConoHa VPS 2GB: 時間課金で上限 2,033円、長期契約で 677〜1,007円（更新時は高くなる）
     - Fly.io（東京）: 約 $9/月（ドル建て）
     - AWS Lightsail: $5〜$12
     - Oracle Cloud 無料枠: 縮小され、東京は空きがないことが多い
     - バックアップ先は Cloudflare R2 の無料枠（10GB/月）で足りる見込み
   - 当時の暫定の第一候補は、さくらのVPS 2GB + docker compose（Caddy / Litestream）。リリース準備のときに改めて選ぶ
2. **CLAUDE.md の「開発フェーズ」**
   - フェーズ2の「完了後: ステージングのデプロイ基盤…」の行を消す
   - フェーズ6（認証）の後に「7. リリース準備」を追加する。中身は、デプロイ先の選定と契約、Dockerfile・本番用 compose・Caddy・バックアップ、ドメイン、リポジトリの Public 化、本番公開。参照先は ADR 0001
   - 今の「7. 展開」は「8. 展開」に繰り下げる
3. **メモリ** `repo-public-before-production`: 「本番移行時」を「リリース準備（フェーズ7）のとき」とはっきり書き直す

## 確認方法
- ADR・CLAUDE.md・設計書を読み合わせて、デプロイのタイミングの記述が食い違っていないことを確かめる
  - 設計書 §6 のロードマップには、ステージングの時期の記述はない
- `git grep -n "ステージング"` で、古い記述が残っていないことを確かめる
- push したあと、CI（ドキュメントだけの変更でも `main` で走る）が成功することを確かめる
