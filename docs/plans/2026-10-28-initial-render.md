# トピックの画面の最初の表示を速くする

## Context
トピックの画面は、HTML が届いたあと JS を読み込んでから、最初の意見（`next-statement`）と分析（`analysis`）を取りに行っていた。
そのため、投票の欄と「みんなの意見」が、ページが出てから少し遅れて現れる（スマホの回線で目立つ）。

## やること
- `topics/[id]/page.tsx`: トピックと自治体に加えて、最初の意見と分析もサーバー側で（Cookie を渡して）並列に取り、`TopicInteraction` に渡す
- `useApi` に `initial` を足す。あれば最初の読み込みはしない（そのあとの読み込み直し・`refreshKey` の変化は今までどおり）
- `VotingPanel`・`AnalysisPanel` は `initial` を `useApi` に渡すだけ
- 最初の意見と分析の取得に失敗しても、ページ全体はエラーにしない（`null` を渡し、今までどおりブラウザ側で取りに行く。エラーとやり直しの表示もそちら）

## 気にしたこと
- 分析を見られないとき（ロック中）も分析 API を呼ぶことになるが、backend は進み具合を見てすぐに `locked` を返すので軽い
- 開発時（React の StrictMode）は effect が2回動くので、ブラウザ側でももう一度取りに行く。本番では取りに行かない

## 確認
- frontend の lint・typecheck・build
- 開発サーバーで: Cookie が無いとき・投票の途中・すべてに投票したあと（分析が開く）で、HTML に最初の意見と分析（またはロックの表示）が入っていること。投票を進めて分析が開くこと

## 実装時の変更点
- 計画どおり。確認は、手元の `data/civic.db` に別のブランチ（`feat/manual-extraction`）のマイグレーションが当たっていて backend が起動しないため、使い捨ての DB に `seed --dev` を入れて行った
- 確認の結果（`next start` で）: Cookie が無いときも投票の途中も、HTML に最初の意見とロックの表示が入る。すべてに投票したあとは、HTML に分析（グループ・関わり方の欄・意見マップの SVG）が入る
