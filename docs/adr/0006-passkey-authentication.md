# ADR 0006: 参加者の認証はパスキーで行い、保存する情報を最小にする

- 状態: 承認（2026-10-28）
- 関連: グランドデザイン §6、ADR 0002（属性で分けない）、ADR 0005（投稿数の上限）

## 背景

フェーズ6（認証）では、ADR 0005 の「1人を見分けて初めて意味がある」決まり（投稿の上限・市民からのトピックの提案）を動かすため、参加者を見分ける仕組みが要る。
グランドデザインでは SNS ログイン（Google・Apple・LINE）を想定していたが、次の点を見直した。

- パスキー（WebAuthn）だけでもログインはできる。名前・メールアドレス・アイコンは要らない
- パスキーで分かるのは「前と同じ鍵を持っている人か」だけで、1人が複数のアカウントを作ることは防げない。SNS も1人1アカウントを保証はしない（手間が増えるだけ）
- 投票は匿名のまま（ログイン不要）と決めた。投票の水増しは防がないので、ログインで守るのは投稿と提案だけになる。投稿には AI の判定と似た意見の案内があり、水増しのアカウントが群がっても Polis の分析は「1つの極端な集団」として扱う

## 決定

- **読むことと投票は、ログインなしでできる**（今の匿名の参加者のまま。署名付き Cookie）
- **意見の投稿と、トピックの提案は、パスキーの登録が要る**
- **ログインはパスキーだけで行う。** SNS ログインは使わない
- **保存するのは、パスキーの公開鍵とその ID、ランダムな利用者の ID、日時だけ。** 名前・メールアドレス・電話番号・端末の名前は保存しない。パスキーに付ける表示名にも個人の情報を入れない
- 投稿の上限（ADR 0005）は**アカウントごと**に数える
- **乱用が見えたら、「1人を見分ける目印」を足す**（フェーズ 6e）。SNS（LINE か Google）か電話番号（SMS）を登録のときに1回だけ確かめ、保存するのは鍵付きのハッシュ（重複は分かるが元に戻せない）だけにする。どちらにするかはそのときに決める（SMS は1通ごとに費用がかかり、SNS はアプリの登録が要る）
- 運営者も同じパスキーでログインする。運営者にするのは CLI から（画面からは運営者を増やせない）

## 理由

- 保存する個人の情報が最も少なく、匿名性の原則（投稿者の情報を API で返さない）を保存の段階から守れる
- SNS へのアプリの登録や Apple の年会費が要らず、ワンオペで保守しやすい
- 投票を匿名のままにしたので、強い本人確認をしても守れるものが少ない

## 影響

- パスキーを失うと（同期していない端末をなくすなど）、アカウントは取り戻せない。メールアドレスを持たないので、本人確認の手段が無い。新しいアカウントを作り直してもらう（前の投稿は残る）
- 1人が複数のアカウントで上限を超えて投稿することは防げない。AI の判定・似た意見の案内・運営者の確認で抑え、乱用が見えたら 6e で目印を足す
- パスキーはドメインに結び付く。本番のドメインを決める（フェーズ7）までは、開発用の localhost で動かす
- ログアウトのあとなどに、パスキーがあるのに新しく作ると、同じ人のアカウントが2つになる（その端末にパスキーがあるかは、サーバーにもブラウザにも分からないため）。2つは自動ではまとまらない。パスキーの表示名に作った日を入れて見分けられるようにし、まとめる機能は重複が実際に起きているかを見てから考える（docs/plans/2026-10-28-phase6a-passkeys.md の「ログインの流れ」）
- 投票はログインなしでできるが、ログインしていない人には投票の前に1回（タブごと）「ログインして投票しますか」を出す。ログアウトしたまま投票して、同じ人が2人に数えられるのを減らすため
- 退会（2026-10-31 追記。docs/plans/2026-10-31-pre-release-pages.md）: パスキー・関わり方・登録と運営者の印を消す。票と意見は残す。もとから誰のものかを返さず、パスキーが無くなれば残る ID は本人にもたどれない乱数になるため。意見そのものを消したい人には、問い合わせから運営者が対応する。端末のパスキーはサーバーから消せないので、対応するブラウザでは `signalUnknownCredential` で端末に知らせ、端末の設定から消す手順も案内する
