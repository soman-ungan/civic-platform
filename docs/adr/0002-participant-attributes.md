# ADR 0002: 参加者の属性の扱い ― 市民を分けて見せない

- 状態: 承認
- 日付: 2026-10-26

## 背景

「住民と関係人口の違い」を可視化する検討の中で、性別・年齢などの観点でも分析を切り替えられるようにするか、市内の地区（黒羽・湯津上・旧大田原市街など）ごとに分けて見せるかが論点になった。

当初はこの論点を、主に個人の特定のおそれ（プライバシー）の観点で検討していた。その後、ユーザーとの対話で次の認識に至った。

> 市民を**本人の属性（年齢・性別など）や市内の地区**で分けて見せることと、**その自治体との関わり方（住民・周辺・通勤通学・関係人口）**で分けて見せることは、分断への影響が本質的に異なる。前者は「〇〇の人たちはこう考える」という対立の構図を作り、分断を煽る。

このプラットフォームの核は Polis の考え方にある。意見グループは**意見だけ**から作り、立場を超えて合意できる点を見つける。人を属性や地域で分けて対比させることは、この目的に反する。

## Polis 本家のやり方（リポジトリで確認、2026-10）

- 性別・年齢などの固定の入力欄は持たない。運営者が「私は20代です」のような**メタ意見**（`is_meta`）を立て、参加者がそれに賛成・反対することで**自己申告**で集める
- メタ意見は**クラスタリングから除外**する（PCA の前に列を 0 で埋める）。意見グループは意見だけで作られる
- レポートでは、できた意見グループを説明するために「各グループの属性の内訳（demographic breakdown of each group）」として示す
- かつて Facebook ログインから性別・生年を推定して保存していた表（`demographic_data`）は、古い仕組みとして残っているだけ

## 決定

### 原則

**市民を、本人の属性（年齢・性別など）や市内の地区で分けて集計・可視化しない。** 分けて見せてよいのは、その自治体との**関わり方**（`residency_type`: 住民・周辺・通勤通学・関係人口）だけとする。

関わり方も、意見グループを作るのには使わない。使い道は、**できた意見グループの説明**（どのグループにも、いろいろな関わり方の人がいることを示す）と、意見ごとの比較に限る。

### 具体的な決定

1. **年齢・性別を必須で集める案は棄却する。** 任意で集めることも当面は行わない。行う場合は、新しい ADR で目的・使い方・公表のルールを決めてからにする
2. **参加者の地区は集めない。** 居住属性を聞くときに地区は尋ねない。API も受け取らない。すでに入っていた値はマイグレーション（`clear_relation_districts`）で消した
3. 使わない列（`users.age_group` / `gender` / `occupation`、`user_municipality_relations.district_id`）は、マージ済みのマイグレーションを書き換えないルールに従って残す。将来、スキーマを整理するときに削除する候補とする
4. **トピックの地区タグ（#黒羽 など）は残す。** 人を分けるものではなく、話題の対象地域を示すものだから
5. 関わり方の集計の公表ルール
   - 5人未満の区分は表示しない
   - **二次秘匿**: 隠した区分の合計が1〜4人になるときは、見えている区分のうち最も少ないものも隠す。合計から引き算で逆算されるのを防ぐため（投票には居住属性の登録が必須なので、合計は他の表示から分かる）
   - 「参加者の中での傾向であり、無作為の標本ではない」ことを明記する
   - 関わり方と他の情報を掛け合わせて公表しない

## 理由

- **分断を生まない**: 本人の属性や地区で市民を分けて見せると、対立の構図が生まれ、それが固定されやすい。特に小さな町の地区は、もともとの地域間の関係を背負っている。関わり方は「このまちとどう関わっているか」という立場で、同じ人でも自治体ごとに変わる。グループの説明に使えば、立場の違う人が同じ意見グループにいることを示せる
- **Polis の原則に沿う**: 意見グループは意見だけで作り、属性は説明にだけ使う
- **個人の特定を防ぐ**: 小さな町で属性を掛け合わせると、個人が特定されかねない。集めなければ、漏れることもない（データの最小化）

## 影響

- 設計書 §3⑤⑥・§4④ を、この方針に合わせて書き換えた
- 可視化は、意見グループごとの関わり方の構成（意見マップの下の帯グラフ）と、意見ごとの関わり方による違い（ドット図）の2つ
- 属性や区分で集計・可視化する機能を新たに検討するときは、プライバシーに加えて「分断を生まないか」を必ず検討する
