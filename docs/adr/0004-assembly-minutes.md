# ADR 0004: 会議録の扱い ― 発言者・引用・最初の意見

- 状態: 承認
- 日付: 2026-10-27
- 計画: `docs/plans/2026-10-27-phase5a-minutes.md`
- 関連: ADR 0002（市民を分けて見せない）、ADR 0003（LLM の運用）、`docs/design/collection.md`

## 背景

市議会の会議録から、市民が賛否を考えられるトピックを作る。会議録には実在の首長・議員・職員の発言が含まれる。取り違えや作られた引用は名誉毀損につながり、名前の出し方しだいで「誰の意見か」で賛否が決まる党派的な分断も生む。AI が作った最初の意見は、市民の議論の枠を決めてしまうおそれもある。

## 決定

### 名前を出すのは、選挙で選ばれた公人だけ

- 首長・議員（議長・委員長を含む）は氏名を出す。公人の名簿（`public_officials`、任期つき）と、会議録の発言者の記載から**機械的に**対応付ける。LLM に人物を推測させない
- 名簿に無い首長・議員がいたら取り込みを止め、運営者が確かめて名簿（seed）に登録してからやり直す
- **職員（副市長・教育長・部長など）は職名だけを出す。** 選挙で選ばれた立場ではないため。AI にも氏名を渡さない

### 引用は原文と一致するものだけ

- 出典の引用は、指定した発言の本文に**そのまま含まれる**ものだけを残す（空白・改行の違いは無視して比べる）。AI が作った引用は捨てる
- 画面には、引用・発言者・会議名・日付と、会議録へのリンクを出す

### 名前は、説明と意見に入れない

- トピックの説明と最初の意見に、名簿の全員と会議録に出てきた全員の氏名が含まれないことをプログラムで確かめる（含まれたら捨てる）
- 意見は誰が言ったかではなく、中身で判断してもらうため（Polis の原則、ADR 0002 と同じ考え方）

### 最初の意見は、議会での主張を出発点にする

- 議員の提案・市の方針・懸念など、**議会で実際に出た主張だけ**を、名前を外した意見（3〜5件）にする。AI に会議録に無い選択肢を作らせない
- 意見ごとに根拠の発言を記録し（`statement_sources`。運営者の確認用で、API では返さない）、実在しない発言を根拠にした意見は捨てる
- 議会に出ていない視点は、参加する市民が足していく。投稿の欄で呼びかけ、Polis の優先度（見た人の少ない新しい意見を多めに表示する）で、あとから出た意見も多くの人の目に触れるようにする
- 議会の議論が一方の立場に偏っていれば、最初の意見も偏る。それは議会での議論の事実であり、足りない視点を市民が補うことがこのサービスの役割と考える

### 下書きと運営者の確認

- AI が作ったトピックは下書き（`topics.status = 'draft'`）にし、運営者が内容・出典・発言者を確かめてから公開する。下書きは API のどこにも出ない
- 運営者は `topics show` で確かめ、`topics edit` / `statement` / `tag` で手直しし、`topics publish` で公開する

### 原本は保持しない

- 手でコピーした会議録は `data/private/`（git の管理外）に置く。DB に残すのは出典（会議名・開催日・URL・ハッシュ）と短い引用だけ
- 自動取得は、議会事務局などの書面の許可を得てから（`docs/outreach/minutes-data-request.md`）

### 形式的な議事は取り込まない

- 議事日程に一般質問・代表質問が無い会議録（会期の決定・上程・採決だけの日など）は取り込まない。基準は自治体ごとに設定で変えられる

## 理由

- 機械的な対応付けと原文との照合で、取り違えや作られた引用を防ぐ
- 名前を出す範囲を公人に限り、意見の文から名前を除くことで、人ではなく政策について考えてもらう
- 最初の意見を議会の主張に限ることで、AI ではなく議会と市民が議論の枠を作る

## 影響

- 運営者は、取り込みのたびに下書きを確かめる手間がかかる（1日分の会議録で5件前後）
- 公人の名簿の保守（改選・辞職・補欠選挙）が要る。任期の正式な日付は要確認（2026-10-27 時点では仮の値）
- 選挙向けの機能（議員ごとの記録）は、この名簿と出典の記録を使って、別の ADR を作ってから検討する（ADR 0003）
