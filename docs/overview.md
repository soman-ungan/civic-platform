# 全体像

地方行政可視化＆市民参加プラットフォームの、今の姿です（2026-10-30、フェーズ6d・タイムラインの流れ・意見の取りまとめ まで）。
当初の構想は [grand-design.md](grand-design.md)（v2）にあり、そこから変わったことは ADR と計画に記録しています。
設計で迷ったら、ここ → 該当する [ADR](adr/) → [design/schema.md](design/schema.md)・[design/api.md](design/api.md) の順に読みます。

## 目的
- 自治体の議事録・予算・決算を分かりやすく見せ、[Polis](https://pol.is/) の思想に基づく合意形成の場をつくる
- 主な対象は10〜30代。スマホファースト
- 多自治体に対応する。栃木県大田原市がパイロット。自治体の追加は、マスタ・地区・収集の設定・人口のデータだけで済み、アプリの改修は要らない
- 個人開発・ワンオペ運用。自動化と保守のしやすさを優先する
- Polis を丸ごとフォークせず、データ構造・画面の考え方・数理（PCA とクラスタリング）を Rust と Next.js に移す。数理は Polis の正式な実装（Clojure）を移植し、一致を確かめている（[polis-math.md](polis-math.md)）

## 画面
| 画面 | URL | 中身 |
|---|---|---|
| トピック（タイムライン） | `/{slug}` | 自治体のトピックの一覧（公開した日の新しい順。新着の印、議会のトピックは会期つき）。分野・地区のタグで絞る。上に「みんなの合意点」の入口。トピックは、タイムラインの上に下から伸びるレイヤで開く（URL の共有・再読み込みでは普通の画面）。締め切ったものは出さない（「これまでの議論」の地図から開く）。下書きは決まった時刻に1件ずつ自動で公開する |
| トピックの詳細 | `/{slug}/topics/{id}` | 説明と議会での議論（会議録の引用）、この分野のお金。意見に1件ずつ投票（賛成・反対・パス）。最初の意見すべてに投票すると「みんなの意見」（意見マップ・グループ・合意点・関わり方ごとの違い）が開き、意見を1件投稿できる |
| みんなの合意点 | `/{slug}/consensus` | 合意点の一覧（締め切ったトピックの分は誰にでも、受付中の分は投票し終えた人に）と「これまでの議論」（締め切ったトピックの地図。タグで絞る。似ているトピックほど近い）。合意点を押すと地図でそのトピックを起点に。起点と近傍を選んでまとめへ。トピック詳細は、このページの上に下から伸びるレイヤで開く |
| まとめ | `/{slug}/digest?anchor=&topics=` | 選んだトピックの合意点・意見が分かれた点・グループの代表的な意見（原文と数字。印刷できる）。ここから次のトピックを提案する |
| 議会 | `/{slug}/council` | 議員の記録（ADR 0008）。首長と議員の一覧（首長が先、議員は読みの順。数では並べない）→ 議員ごとに、その人の発言が出典になったトピック（分野で絞る）→ 発言の引用と会議録へのリンク。取り込んだ会議録の範囲を添える。トピック詳細の「議会での議論」の議員名からも開く |
| まちのお金 | `/{slug}/finances` | 決算カード（目的別・性質別・歳入、1人あたり、年度の推移）と当初予算（主な事業のツリーマップ） |
| このサービスについて・利用規約・プライバシーポリシー | `/about`・`/terms`・`/privacy` | 目的・原則・運営者・収支の公開先・問い合わせ（`NEXT_PUBLIC_CONTACT_EMAIL` のメール）。規約とプライバシーポリシーは、パスキーを作るときに同意してもらう |
| アカウント | `/account` | ログアウトと退会（パスキー・関わり方・登録の印を消す。票と意見は匿名のまま残す。ADR 0006） |
| 管理画面 | `/operator` | 運営者だけ。下書きのトピックの確認と公開（似ているトピックの候補・まとめから生まれたトピックの元のトピックつき）、公開待ちと公開の時刻、確認待ちの意見の採否、公開中のトピックの期限 |

- 有効な自治体が1つの間は、`/` からそのトップへ移る（選択の画面はフェーズ8）
- コメント欄・リプライは作らない（Polis の原則）
- 全ページのフッターにソースコードへのリンク（AGPL 第13条）と「このサービスについて」
- ページごとの題と説明を、共有したときの表示（Open Graph・X のカード）にも入れる（`lib/metadata.ts`。基準の URL は `NEXT_PUBLIC_SITE_URL`）

## 原則（詳しくは ADR）
| 原則 | 要点 | ADR |
|---|---|---|
| 多自治体 | 大田原市をコードに書かない。データは必ず `municipality_id` で絞る。分析は自治体をまたいで混ぜない | — （CLAUDE.md） |
| 分断を生まない | 市民を年齢・性別・地区で分けない（集めない）。分けて見せてよいのは関わり方（住民・周辺・通勤通学・関係人口）だけで、それもグループ作りには使わない。5人未満の区分は隠す | [0002](adr/0002-participant-attributes.md) |
| AI の運用 | API キーが無くても動く。判定できないときは自動で承認しない。AI に送るのは本文と公開済みの内容だけ。資料の収集はエージェントにしない | [0003](adr/0003-llm-operations.md) |
| 会議録 | 名前を出すのは選挙で選ばれた公人だけ。引用は原文どおり。最初の意見は議会で実際に出た主張だけ。AI が作ったトピックは運営者が確かめてから公開 | [0004](adr/0004-assembly-minutes.md) |
| トピックの寿命と資金 | トピックは公開から90日。締め切っても結果は読める。意見は1人1件。お金で議論への影響を変えない。行政・政党からの資金は受けない。締め切ったトピックは市民がまとめ、次のトピックを提案する（中身はプログラムだけで決め、AI でまとめない） | [0005](adr/0005-topic-lifecycle-and-funding.md) |
| 認証 | パスキーだけ。読む・投票はログインなし、投稿は登録が要る。保存するのは公開鍵・ID・日時だけ | [0006](adr/0006-passkey-authentication.md) |
| 意見の審査 | 主張や政治的な立場では判断しない。害・人物・投票できるか・似た意見を別々に見る。公人の政策への批判は公開、人格攻撃は非公開 | [0007](adr/0007-statement-review.md) |
| 議員の記録 | 議員の仕事ぶり（議会で取り上げたトピックと原文の引用）だけを見せる。順位・評価・立場の推測はしない。記録は会議録から機械的に対応付ける | [0008](adr/0008-elected-officials-and-elections.md) |
| 配置 | Docker はリリース準備（フェーズ7）でまとめて入れる | [0001](adr/0001-docker-adoption.md) |

## 構成
```
civic-platform/
├── backend/    Rust / axum / sqlx。API サーバーと運営のコマンド（同じバイナリ）
│   └── src/    interface（API・CLI）→ ingest（資料を DB に）/ records（DB を見る・直す）/
│               process（判定・計算: 審査・タグ付け・分析・参加のルール）/ maintenance（seed・eval）→ shared
├── frontend/   Next.js（App Router）/ TypeScript / Tailwind CSS
├── data/       SQLite（開発）と seeds（自治体・地区・タグ・公人の名簿）
└── docs/
```
- DB は開発は SQLite、将来 PostgreSQL。両方で動く SQL で書く（CI で PostgreSQL へのマイグレーションと seed を確かめる）。テーブルは [design/schema.md](design/schema.md)
- API は [design/api.md](design/api.md)
- サーバーの中では、分析（投票が変わったトピック）・判定待ちの意見の再判定・自動のタグ付け・下書きの自動公開が定期的に動く
- 似ているか（同じ論点のトピック・同じ意見・地図の配置と近傍）は、文字の2-gram の類似度で計算する（`process/similarity.rs`。トピックと意見に共通。API キーは要らない）。同じ論点か・同じ意見かの判定は AI か運営者

## データの入り方
- 資料は3種類: 決算カード（総務省、全国共通。AI を使わない）、当初予算の概要（市の PDF）、会議録（手でコピー）
- どれも `fetch` → `extract`（AI）→ `import`（検査して保存）の同じ流れ。AI は API でも、Claude Code との共同作業（費用 0）でも使える
- 予算と会議録から作ったトピックは下書きになり、運営者が確かめてから公開する。原本は保持しない
- 流れの図は [operations/data-flow.md](operations/data-flow.md)、コマンドは [operations/cli.md](operations/cli.md)、収集の方針は [design/collection.md](design/collection.md)

## まだ決めていないこと
- 議員ごとの記録（会議録の発言者の記載から機械的に対応付ける。選挙向けの機能は ADR を書いてから）
  - 2026-10-30 のユーザーの希望: 選挙のページを作り、議員ごとにトピックや意見をひも付けて志向を見られるようにする。できれば今のクラスタリング（`process/analysis/`）で、議員を政策の方向性でグループに分ける。公職選挙法と「分断を生まない」（ADR 0002）を ADR で整理してから着手する
- 寄付の受け付けと収支の公開の方法（フェーズ7）
