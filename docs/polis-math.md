# Polis の数理処理の移植

投票の分析（PCA・クラスタリング・代表意見・合意点・表示順の優先度）は、本家 Polis の正式な実装を Rust に移植したものです。ライセンスは Polis と同じ AGPL-3.0-only です。

- 移植元: https://github.com/compdemocracy/polis の Clojure 実装 `math/src/polismath/math/`
  - ブランチ `edge`、コミット `b4971eee61e4c8efa3d0f47f9b2a8bee3c9c50f9`（2026-10-26 時点）
  - pol.is の本番で動いてきた基準実装。Python 版 `delphi/` は、これと一致させることを目的にした移植
- 参照した資料: `delphi/docs/CLOJURE_QUIRKS.md`（癖と不具合の一覧 Q1〜Q19）、`delphi/docs/MATH_ALGORITHM_HISTORY.md`（変更の経緯）

## 処理の流れ

1. **投票行列**: 行 = 参加者、列 = 意見。値は Polis の符号（**賛成 = -1、反対 = +1**、パス = 0、未投票 = なし）。このプロジェクトの DB は賛成 = 1 なので、行列を作るときに反転する。行と列は最初に投票された順に並べ、次回の計算に引き継ぐ。
2. **モデレーション**: 承認されていない意見の列は 0 で埋める（`zero-out-columns`）。集計（group-votes）は埋める前の行列から行う。
3. **in-conv**: `min(7, 意見数)` 件以上投票した参加者を分析に含める。15人に満たなければ、投票数の多い順に補う。一度入った人は外れない。
4. **PCA**: 欠損を列の平均で補い、平均を引いて、べき乗法（100回）で主成分を2本求める。前回の主成分を初期値として引き継ぐ。
5. **射影**: 参加者は投票した意見だけで内積を取り、`√(意見数 / 投票数)` 倍する。意見の射影は「その意見だけに賛成した人」の位置で、その長さが extremity。
6. **基底クラスタ**: in-conv の参加者の射影を k-means（k = 100、反復 100、前回のクラスタから clean-start）。
7. **グループ**: 基底クラスタの中心を人数で重み付けした k-means を、k = 2〜`min(5, 2 + ⌊基底クラスタ数/12⌋)` で計算し、シルエット係数が最大の k を選ぶ。group-k-smoother により、同じ k が4回続いたときだけ切り替える。
8. **代表意見**: グループ内とそれ以外で賛成・反対の比率を比べ（擬似カウント `(x+1)/(n+2)`、z 検定）、90% で有意なものから最大5件。
9. **合意点**: Polis の consensus（全体で確率 > 0.5 かつ 90% で有意、上位5件）と、group-aware consensus（グループごとの `(A+1)/(S+2)` の積）。
   - タイムラインのピン留めは、このプロジェクトの判断で「全グループで `(A+1)/(S+2)` ≥ 0.8」とし、group-aware consensus の大きい順に並べる。
10. **表示順の優先度**: `(importance × (1 + 8·2^(−S/5)))²`、`importance = (1 − p)(E + 1)a`。未投票の意見から、優先度で重みを付けた乱数で選ぶ（優先度の無い意見の重みは 1）。

## パラメーター（すべて Polis と同じ）

| 名前 | 値 |
|---|---|
| 主成分の数 / べき乗法の反復 | 2 / 100 |
| 基底クラスタの k / 反復 | 100 / 100 |
| グループの k の上限 | 5 |
| グループの k-means の反復 | 20（下の Q3） |
| group-k-smoother のバッファ | 4 |
| in-conv の最小投票数 / 補う人数 | 7 / 15 |
| 有意水準（片側 90%） | z > 1.2816 |
| メタ意見の優先度 | 7（このプロジェクトにメタ意見はない） |

## Polis の癖・不具合の扱い

番号は `delphi/docs/CLOJURE_QUIRKS.md` のもの。

| 番号 | 内容 | このリポジトリ | 理由 |
|---|---|---|---|
| #2611 | メタ意見の判定の不具合で、優先度がすべて 49 になる（2025-03〜2026-07） | **修正後を採用** | Polis で修正済み（`edge` に入っている） |
| Q12 | コールドスタートの PCA 初期ベクトルが乱数 | **すべて 1 に固定** | Polis 自身が検証で使う方法。元の作者のコメントでも、シード固定が TODO になっている。結果が毎回同じになる |
| Q2 | 優先度が前回の計算の group-votes から出る | **今回の group-votes を使う** | 明らかな不具合。Python 版の改善モードと同じ |
| Q3 | グループの k-means に指定した反復回数（100）が無視され、20 で動く | **20 を再現** | 実際に動いてきた値に合わせる |
| Q7 | サブグループ（2段目のクラスタリング） | **移植しない** | Polis でも、どこからも使われていない |
| Q10 | 大規模な会話でのミニバッチ PCA（乱数あり） | **移植しない** | 想定する規模では不要。常に通常の PCA を使う |
| Q11 / Q17 / Q13 / Q18 | 浮動小数点の桁落ちや Clojure のハッシュ順による同点の扱い | **再現しない** | 実装の偶然による挙動。距離は通常のユークリッド距離で計算し、同点は「後のものが勝つ」（`min-key` / `max-key`）を入力の順で適用する |
| Q4 / Q5 / Q14 / Q16 | 参加者・意見がごく少ないときも計算を続ける | **参加者か意見が2未満なら計算しない** | Python 版の改善モードと同じく「データ不足」を返す |
| Q1 | 投稿を禁止された参加者が計算に残る | 該当なし | このプロジェクトには、まだ参加者の禁止機能がない |

このほか、異常な場合の扱いとして、次の2点を加えている。

- clean-start で、メンバーがすべて今回のデータにいないクラスタの中心は、前回の中心を保つ（Clojure では NaN になる）
- シルエット係数で、比べる相手のクラスタが無い場合は 0 とする（Clojure では例外になる）

## 一致テストの結果

`backend/tests/polis_parity.rs` で、Polis の公開データ biodiversity（参加者 536人、意見 314件、CC BY 4.0）を一度にまとめて計算し、Clojure 版のコールドスタートの出力と比べている。合否の基準は、Polis 自身の比較テスト（`delphi/tests/test_legacy_clojure_regression.py`）に合わせた。

| 項目 | 基準 | 結果 |
|---|---|---|
| in-conv | 完全一致 | 441人で**完全一致** |
| 主成分 | 角度 10° 以内 | PC1・PC2 とも **0.0000°** |
| グループ | 数が一致、Jaccard の平均 0.99 以上、人数分布の差 0.01 以内 | 2グループ、Jaccard **0.993**、差 **0.0045**（441人中1人だけ所属が異なる） |
| 代表意見 | （Polis の Python 版では未一致の扱い） | 両グループとも、5件の tid と並び順が**完全一致** |
| 全体の合意点 | 完全一致 | 賛成・反対とも、同点の並びまで**完全一致** |
| group-aware consensus | 差 0.01 未満 | 最大の差 **6.8e-3**（上の1人の違いによる） |
| 優先度 | — | 正解データは #2611 の不具合で全部 49。このリポジトリは修正後の式なので比べない（式は単体テストで確認） |

グループの所属が1人だけ異なるのは、基底クラスタ（100個）の段階で同点の扱い（Q11 / Q17）が異なるため。行の並びを変えても結果は変わらないことを確認した。

なお、正解データの列は意見 ID の昇順に並んでいる。統計値がまったく同じ意見の並び順は列の順で決まるため、一致テストでは行と列を ID の昇順に並べてから計算している。
